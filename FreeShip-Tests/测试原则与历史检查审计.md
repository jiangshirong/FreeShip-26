# 界面测试设计与历史检查审计

用户要求：先提供客观的入口、状态和行为证据，供 AI 结合当次需求判断界面设计；不要把某个按钮或功能固定在哪个入口当作默认正确性。此原则适用于以后新增的测试。

## 已调整

- 旧工具栏位置、固定中俄文措辞和指定宽度下的溢出断言已退役，改为记录结构及动态内容；部分视图功能启用条件、文字边界和固定译文识别保留为 `review`，不将设计差异自动判为失败。
- 旧按钮行为测试若因原按钮不存在而无法执行，标为 `not_run`。语言输入保护、选中状态、数据保存和撤销重做等行为断言保留。
- 新增多状态结构快照与状态差异，记录菜单树、动作、快捷键、控件、组合框条目和显示/启用状态。该数据是观察结果，不判定位置是否合理。

## 已迁移的行为检查和限制

- 坐标测试现按已核查的事件处理器身份与参数发现菜单项；缺失或不唯一时标记 `not_run`。处理器本身是已知功能适配器，并非任意新功能都能自动识别。箱体数值及绘图预期是独立行为验证。
- 快捷语言和选择全部从已发现的菜单项或动作读取快捷键，再在进程内执行并观察状态变化；找不到唯一入口时为 `not_run`。真实键盘、焦点和模态事件仍未测试。
- 图层表格按事件绑定发现，扫描单元格关联的模型对象与复选列，试探各列对模型属性的作用并记录 `layer_discovery`；批量开关和图层选择器按回调绑定发现。作用无法唯一识别时为 `not_run`，不把缺失的入口或推断不到的列判为产品失败。
- 点名称输入按编辑事件发现；坐标编辑器按共享事件发现并检查已知样本数值集合。这不证明每个数值对应的轴标签是否正确。
- 溢出菜单及工具栏缩放适配器按回调身份发现，动作及按钮按事件和绑定发现；匹配不唯一时停止该检查。安全策略按源码哈希核准，源码更新后需重新审查。
- 上述行为探针仍使用明确的 FreeShip 处理器方法、模型属性和隔离样本作为功能适配器；处理器签名或模型 API 变更时可能需要更新适配器，不能声称可自动理解任意新功能。结构库存不等于完整 UI 验收。
- 标签检查使用已知箱体、尺寸及绘制数据；固定翻译文本识别的参考线已降为复核。它验证绘制数据及几何边界，不用于判定入口位置。其他模型、视觉可读性和密集模型标签仍未全面验证。
- 静态库存枚举当前已构造组件；单独的动态进程对哈希核准的弹出及下拉回调采集前后数据。未知回调、未构造对话框及系统交互仍未覆盖；`not_run` 不代表动态项不存在。
- 菜单路径使用序号辅助区分同名项；动态插入或排序会改变序号，状态差异是定位线索，不是语义等价证明。

## 验收边界

`inventory.json` 应与同目录 `report.json` 的源码哈希和状态一起阅读；源码或测试代码运行期间变化时，总结果为 error，不可验收。屏幕、焦点、物理键盘、模态窗口和可访问性树未由本工具证明。

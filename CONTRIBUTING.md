# Contributing to FreeShip_26

Bug fixes, documentation improvements, build reports, and help with cross-platform development are welcome. You can contribute by testing a build or reporting a reproducible problem, even if you do not have a patch.

- **Small fixes and documentation.** Open a focused PR against the branch that contains the code or documentation you are changing.
- **Qt, Linux, or macOS work.** Start or join a related issue before making substantial changes so we can agree on the source branch and scope. Build testing and packaging help are welcome, including early results and build failures.
- **Testing.** List the operating system, CPU architecture, and relevant toolchain versions. Describe what you built or ran, how to reproduce it, and which platforms or workflows you did not test. For packaging changes, distinguish building the package from installing and launching it.
- **Engineering behavior.** If your change touches FBM files, hull geometry, calculations, or exports, explain any intended change in behavior and include a reproducible sample or comparison. Platform fixes should preserve existing file compatibility, calculation accuracy, and export semantics.
- **Shared work.** Credit each co-author using the email linked to their GitHub profile. Put all `Co-authored-by:` lines together at the end of the commit message, with no blank lines between them.

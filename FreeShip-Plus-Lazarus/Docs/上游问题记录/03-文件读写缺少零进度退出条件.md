# 文件读写缺少零进度退出条件

状态：已修复（低层读写回归通过）。优先级：P1。

读写循环用实际完成的字节数推进位置，却没有处理返回零字节的情况。如果文件在读取期间被截断，或者写入持续无法前进，循环条件可能一直成立，程序也没有机会报告失败。

剩余数据未处理完而本次进度为零时，应立即报错。短读、短写也要明确处理，并保证文件句柄被关闭。收益是把无法完成的读写变成可退出的错误，避免程序一直等待。

代码位置：`Units/FreeFileBuffer.pas`，`TFreeFileBuffer.LoadFromFile`、`SaveToFile`。见[读取循环](https://github.com/markmal/freeship-plus-in-lazarus/blob/1de17e99fb2b1cc559cdf27c5cafb595a627a641/Units/FreeFileBuffer.pas#L2177-L2191)、[写入循环](https://github.com/markmal/freeship-plus-in-lazarus/blob/1de17e99fb2b1cc559cdf27c5cafb595a627a641/Units/FreeFileBuffer.pas#L2216-L2227)。

原始检查（修复前）：已核对循环条件，未注入底层读写故障。修复验证需要覆盖零进度、部分完成和正常读写。

## 本项目修复（2026-10-30）

`FreeFileBuffer.pas` 增加可复用的流读写接口。短读短写会继续处理；还剩数据但返回零、负数或超出请求长度时立即报错。文件句柄在 `finally` 中关闭，打开失败直接保留原异常，不再改变全局 `FileMode`。

读入完整之前不替换原缓冲。文本格式也走同一套完整读写机制；共享的记录读取按二进制和文本分别校验，避免把文本行数当作二进制长度。

65 项低层回归通过，包括每次仅处理 3 字节、首次及中途停滞、异常返回、句柄释放、二进制和文本非零记录、JPEG 长度。见[低层报告](../../../FreeShip-Tests/reports/buffer-safety-ftm-final-20261030/report.json)。没有模拟物理磁盘满或断电。本次为本地修改，尚未创建 Git 提交。

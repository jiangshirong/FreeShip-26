# 外部计算缺少超时和退出码处理

状态：已修复已列出的进程错误、结果隔离和格式校验；旧协议本身的限制见文末。优先级：P2。

以下问题描述为修复前核对，修改进展见文末。

外部程序的等待循环没有超时或取消条件，子程序卡住时会一直等下去。执行包装函数返回的是启动和收集输出的结果，子程序自身的退出码只是写入日志，非零退出没有被直接作为失败传回。

应统一返回启动错误、退出码、超时和取消状态，失败时停止读取计算结果。每次计算使用独立临时目录，检查本次输出确实完整生成，避免继续处理旧结果。

代码位置：`Units/freeprocess.pas`，[`internalRuncommand` 的等待循环](https://github.com/markmal/freeship-plus-in-lazarus/blob/1de17e99fb2b1cc559cdf27c5cafb595a627a641/Units/freeprocess.pas#L35-L79)、[`ExecuteFreePlugin` 的返回值处理](https://github.com/markmal/freeship-plus-in-lazarus/blob/1de17e99fb2b1cc559cdf27c5cafb595a627a641/Units/freeprocess.pas#L148-L157)。

初次核对时只检查了源码。后续两批已运行启动失败、非零退出、超时、取消和正常结果的专项测试。

## 第二批修复（2026-10-30）

`Units/freeprocess.pas/RunFreeProcess` 现在区分启动失败、退出错误、超时、取消及读写错误，记录退出码和耗时。计算默认最长等待 120 秒，可由参数或 `FREESHIP_PLUGIN_TIMEOUT_MS` 调整；标准输出和错误输出持续排空，各自最多保留 1 MiB，避免管道写满后双方等待。

`ExecuteFreePlugin` 遇到这些失败会抛出 `EFreePluginError`，调用方不会继续读取失败计算的输出。相关计算方法用 `finally` 恢复工作目录和鼠标状态。交互式数据库查看器单独异步启动，不套用计算超时；需要后续计算的入口仅在查看器正常退出后继续。

`Forms/FreeHydrodyn_ManeuvDlg.pas/Calculate` 原来在子程序正常退出、但没有生成 `OUT` 时仍会无限循环。现在立即报告缺少结果文件，并恢复原工作目录与鼠标状态；测试包含预置旧 `OUT` 后运行不产出结果的子程序。

入口：`python -B FreeShip-Tests/process_safety.py` 和 `python -B FreeShip-Tests/process_callers.py`。检查成功、非零退出、启动失败、超时、取消回调、大量两路输出，以及实际计算入口发生错误后的状态恢复。没有验证数值插件本身的计算正确性或桌面操作。

第二批结束时，尚未完成独立目录和结果格式校验，因此当时保留“部分修复”。当时源码及报告仍由第二批总记录归档。终止直接子进程、取消接口没有桌面按钮这两个范围限制仍然有效。

已经逐处整理 [29 个计算调用与 3 个查看器的文件协议](../../../FreeShip-Tests/reports/process-contract-design-20261030/contract-inventory.md)。部分任务会读取前一次阻力或螺旋桨计算生成的数据，不能简单给每个程序换一个空目录。

## 第三批修复（2026-10-30）

现在从输入文件导出到结果解析都在本次计算独有的 `job-{GUID}` 目录内完成。每次启动子程序前删除本轮输出，退出成功后才检查文件；缺失、空文件、非法数字、超出数组容量、固定记录不足，都会在旧读取循环前报错。需要成对生成的螺旋桨报告和曲线文件一起检查。原先某些入口把读取异常改成零值的处理也已移除。

跨任务只传递明确声明的 `RESIST.dat`、`RESISTp.dat`、`Propres.dat`，缓存按模型几何、单位和主要工况区分。重算先撤销旧结果，成功后验证整组文件，再一次性切换到新的缓存目录。同模型计算有文件锁，失败不会留下半份新结果供下一步读取。配置和阻力数据库按需要复制；三个数据库查看器仍走原来的独立入口。

当前代码位置：

- `Units/FreeCalculationFiles.pas:118`，`TFreeCalculationScope.Create`：独立目录、模型锁、输入传递、旧结果失效。
- 同文件 `:244`，`PublishFiles`：结果校验及整组发布；`:288`，`ValidateFreeCalculationOutput`：22 种文件格式；`:364`，`ExecuteFreeCalculation`：清理本轮输出、启动及校验。
- `Units/FreeShip.inc:4073`，`CalculationRoot`：模型缓存标识。
- `Units/FreeEdit.inc:2556` 及各计算窗体的 `CalculateInWorkspace`：覆盖附加质量和 16 个计算窗体。例如 `Forms/FreeResistance_MHDlg.pas:598`。
- `Units/FreeSafeFile.pas:195`，`ReplaceFileAtomically`：切换缓存目录指针时使用同目录临时文件和原子替换。

验证入口是 `calculation_contracts.py`，并已接入 `improvement_regression.py`。本次 124 项通过：22 种结果格式的正常、缺失、空、截断、非法数字检查，另有隔离、旧文件、失败失效、重新计算、跨任务传递和成对输出检查。六个作者发布的滑行艇计算程序，用相同输入分别直接运行和经过新流程运行，输出逐字节相同。原有进程测试 30 项、实际调用方测试 23 项也通过。样本和二进制来源见[测试资料说明](../../../FreeShip-Tests/fixtures/README.md)。

这里的“完整性”有边界：有些旧文本协议没有记录总数、结束标记或校验和，若文件恰好在允许的完整行边界截断，无法单凭输出识别。固定字段、数组容量和缺失配套文件可以检查，但不能据此保证插件数值算法正确；真实二进制对照目前覆盖上述六个程序。临时缓存保留历史发布目录，尚未增加自动清理策略。

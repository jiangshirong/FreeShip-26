# 重建异常后状态不复位

状态：已修复，验证范围见下文及第二批总记录。优先级：P1。

以下问题描述为修复前核对，修改进展见文末。

几何重建开始时把 `FIsBuilding` 设为真，只在正常结束处恢复。中间没有 `try…finally`；一旦细分、曲线重建或回调抛出异常，后续重建和绘制就可能一直因“正在重建”而直接退出。

忙碌标志必须在退出时恢复，重建失败也不能把模型标成构建成功。应保留明确的失败状态，让用户能够撤销、重新加载或再次重建。

代码位置：`Units/FreeSubdivisionSurface.inc`，`TFreeSubdivisionSurface.Rebuild`。见[设置重建标志](https://github.com/markmal/freeship-plus-in-lazarus/blob/1de17e99fb2b1cc559cdf27c5cafb595a627a641/Units/FreeSubdivisionSurface.inc#L4582-L4594)、[正常结束才复位](https://github.com/markmal/freeship-plus-in-lazarus/blob/1de17e99fb2b1cc559cdf27c5cafb595a627a641/Units/FreeSubdivisionSurface.inc#L4681-L4687)。

已核对源码，未注入重建异常。修复时应故意让重建中断一次，再检查后续绘制和恢复操作是否仍可执行。

## 第二批修复（2026-10-30）

`FreeSubdivisionSurface.inc/TFreeSubdivisionSurface.Rebuild` 用 `try…finally` 恢复 `FIsBuilding` 和 `FRebuildRequested`，只有完整重建结束才设置 `FBuilt=True`。失败不会把半成品标成已经构建。

入口：`python -B FreeShip-Tests/file_safety.py --case geometry`。在真实 `OnFaceRebuilt` 回调中抛出异常，检查状态复位，再对同一个 Surface 重新构建。未用桌面工具验收绘制；最终源码及报告由第二批总记录统一归档。

最终验证、剩余范围与程序更新见[第二批修复记录](第二批修复-计算与异常处理.md)。

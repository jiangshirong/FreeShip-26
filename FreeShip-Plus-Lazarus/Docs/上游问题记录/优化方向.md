# 从历年讨论留下的优化方向

核对日期：2026-10-29。编号 O01–O14 用于追踪需求，全部尚未完成实施验收。它们包括已有功能的改进、工作流补齐和待验证线索，不都属于代码缺陷。资料编号对应[逐项核对表](资料逐项核对表.md)，每个来源都能回到原网址。Units/、Forms/ 等代码位置相对 `FreeShip-Plus-Lazarus`；`FreeShip-MCP` 和 `FreeShip-Tests` 是项目根目录下的并列目录。

## O01　自动恢复、备份和启动容错　P1

现有 `.Bak` 是保存时的备份，撤销记录也不等于进程退出后的恢复文件。代码检索未发现完整的定时恢复快照流程。增加独立于正式文件的轮换快照，启动时先展示恢复候选，不覆盖原件。云同步目录要检查写入中断、冲突副本和重新打开，不能把 GH-90 中对 OneDrive 的怀疑当作已确定原因。

预览图生成失败不应连带阻止模型数据保存。当前 `FreeProjectSettings.SaveBinary` 会在写项目时调用 `FGetPreview`；恢复快照可跳过预览。最近项目损坏或资源目录失效时，应允许跳过自动加载并进入恢复/选择界面，而不是要求用户删配置或删模型。

位置：`Units/FreeEdit.inc` 的 `File_Save`；`Units/FreeProjectSettings.inc:568`；`Units/FreeShip.inc` 的 `FGetPreview`；`Forms/Main.pas` 的 `InitiallyLoadModel`。来源 U05、GH-52、GH-77、GH-90、GH-104。与记录 01、02、17 一起验证；旧 GH-6 的截图保存故障不重新登记为当前缺陷。

## O02　几何检查给出对象和原因　P1

已有 `Model_Check` 会检查并修改部分法向、边和面，漏点提示只列前十个坐标。它不是完全只读的检查，也不能由一句“模型正常”推导出没有自交、重叠或所有计算条件都满足。

把检查和修复分成两步。先列出点、边、面编号与位置，支持定位、筛选和修复预览；修复作为可撤销的单独操作。补充重复面、零面积面、极短边、自交候选及开口与当前水面的关系。保留现有容差设置，说明阈值所用单位；按模型尺度做测试。U09/U11 的负值、漏点和折痕问题只能作为样例线索。

位置：`Units/FreeEdit.inc:7574` 的 `Model_Check`、`Point_IntersectLayer`；`Units/FreeSubdivisionSurface.inc` 的 `CheckIntegrity`；`FreeShip-MCP/src/freeship_mcp/quality.py`。来源 U04、U09、U11、U18、GH-72。原 GH-64/GH-65 的合点缺陷已有修复，不照搬其旧结论。

## O03　吃水、基线和报告使用同一口径　P1

水面构造使用参与静水力计算的最低点，再加输入吃水和纵倾。报告部分字段又加回模型最低 Z。用户看到输入吃水与报告不同，需要知道是坐标基准变化，还是模型实际变化。

在计算前展示模型最低 Z、基线、设计水面绝对 Z、有效吃水及各系数基准，报告沿用同样名称。模型平移、修改主尺度和切换单位时显示影响。不要因为 U02 的两个数值不同，就宣布排水量积分错误。

位置：`Units/FreeHydrostaticCalc.inc:25` 的 `FGetWlPlane`、`AddHeader`、`AddFooter`；`Units/FreeProjectSettings.inc`；`FreeShip-MCP/docs/numerics.zh-CN.md` 已有部分基准说明，可供界面统一。来源 U02、U09、GH-72。与记录 05–07、12 配合。

## O04　板材从展开结果到裁板文件　P2

当前已有展开、边误差显示、TXT 边界坐标、DXF 和打印。不能再写成“没有这些输出”。剩下的工作是把对应板缝两侧边长放在一起比较，保留板号、方向、单位、镜像关系和接缝编号，并清楚区分原始轮廓与加工余量。

建立同一船型两侧、不同分片和不同细分级别的展开对照。平面和圆柱面作基准，双曲率板作为误差示例。纸板试拼能帮助判断，但不是材料应变或实船加工的数值验收。TXT/打印的历史崩溃已经修复，不作为新缺陷计数。

位置：`Units/FreeDevelopedPatch.inc` 的 `Unroll`、`SaveToTextFile:1051`；`Forms/FreeExpanedPlatesDlg.pas` 的 `ExportTextFileExecute`、DXF 与打印动作。来源 U03、U15–U17、U19、U20、U25。误差指标另见记录 16。

## O05　导出单位、缩尺与网格精度　P2

STL 当前直接写模型坐标，没有独立的目标单位和模型比例选择。增加单位、缩尺、导出包围盒及三角面数量预览。网格精度应按允许的弦高/偏差选择，保留折角，避免把“高精度”与“适合打印”直接画等号。

STL 本身不保存单位，不能认定输出米就是违反格式。OBJ 的说明性单位注释也不能保证接收软件自动换算。用已知尺寸模型跨切片器/CAD 比较，检查单位、法向和非对称部分。

位置：`Units/FreeEdit.inc:4188` 的 `File_ExportSTL`、`File_ExportObj`；`Units/FreeSpline.inc`；`Forms/FreeLinesplanFrme.pas` 的 `AddSpline`。来源 GH-121、U07、GH-79。镜像问题另见记录 13。

## O06　CAD 交接后的曲面质量　P2

IGES 已经输出 NURBS 曲面，不是只能输出网格；当前 Type 128 末尾也已有 U/V 范围，旧版 I02 所述缺失不再登记。可改进的是控制碎片数量、边界间隙、相邻片连续性和缝合后的拓扑，并保留图层、名称与对称设置。

导出后用独立 CAD 重新读取，测量边界偏差、缝合情况和抽壳结果。Onshape 的抽壳失败不能单独证明 IGES 非法。STEP、IGES/3DM 导入作为独立格式扩展评估，不能把接口换成 STEP 就宣称解决了曲面质量。

位置：`Units/FreeEdit.inc` 的 `File_ExportIGES`；`Units/FreeIGESUnit.pas:144` 的 `Add_Entity_128`；`Units/FreeNURBSurface.inc`。来源 U06、I01–I03、I11、I12、GH-20、GH-86。地区小数点已有修正，后续属于格式回归。

## O07　面向 3D 打印的封闭与厚度检查　P2

开放的船壳能显示，不代表切片器能把它当成实体。增加“用于静水力”与“用于打印”的检查范围，列出需要封闭的甲板、艉板、内外壳和法向问题。厚度字段用于板材重量等计算，不应让用户误认为已经生成了内壳。

可以先输出明确诊断和 CAD 衔接步骤，再评估实体化/偏置工具。验证封闭模型、开放艉板、薄壁模型和局部厚度；偏置后的自交要单独检查。U07 后续已成功打印，不作为“无法打印”的现存 bug。

位置：`Units/FreeEdit.inc` 的 `File_ExportSTL`、`Model_Check`；`Units/FreeSubdivisionLayer.inc` 的厚度与对称设置。来源 U06、U07、GH-79。

## O08　OBJ 保真导入和指定型线拟合　P2

当前 OBJ 导入主要读取顶点与面。原网格当控制网后，细分光顺可能改变外形。应让用户明确选择保持网格形状、作为参考，或拟合为可编辑控制网，并报告拟合误差。平滑组/法线与其他软件的“锐边”语义要分别解释，不能全部去掉硬边。

对指定站线、旧型线图和点云，增加带锁定点和误差范围的拟合流程，控制网格数量与偏差同时显示。已有锁点、锚点、直线约束和 Lackenby 变换可复用，不能写成完全没有约束或船型变换。OBJ 负索引、空白分隔及错误行提示也应列入导入样例。

位置：`Units/FreeSubdivisionSurface.inc:2609` 的 `ImportObjFile`；`Units/FreeEdit.inc` 的 `Point_ProjectStraightLinePermanentConstraint`、`Model_LackenbyTransformation`；`Units/FreeSubdivisionControlPoint.inc`。来源 GH-120、I04、I01、U10。

## O09　背景图标定和新手操作说明　P2

当前已有 `emSetScale` 和拖动边框 `emSetFrame`，GH-101 的鼠标缩放请求已实现。保留的改进是把现有操作整理成清楚的导入、选视图、选参考长度、检查比例和原点的过程，给出数值与图形反馈，并让帮助图片随版本保存。

2026-10-30 的两个随附 Tug 样本还发现背景图保存会重新压缩 JPEG：位置、比例和尺寸不变，但解码像素有轻微变化。后续应保留未编辑图像的原压缩数据，避免反复保存积累损失。证据见 [背景图分块与像素报告](../../../FreeShip-Tests/reports/legacy-settings-pieces-pixels-20261030/report.json)。这是待做的保真改进，不计入记录 14 的空引用修复。

## O10　附体、分舱与内部结构的衔接　P3

已有平面求交、图层求交点、插入点和面、圆柱体等工具。论坛中“细分曲面不能求交、只能用四边面”的断言不能照抄。实际缺口是求交后怎样裁切、合并、保留拓扑，连接船壳与龙骨/附体，并确认水密性和连续性。

分舱体积、气舱浮力、肋骨与舱壁需要明确的对象和边界，不能仅靠图层名称或一条站线代表。先做任务范围内的封闭体测量与结构线输出，再决定留在本程序还是交给 CAD。验收包括接缝、重叠体积、图层计算标志和往返编辑。

位置：`Units/FreeEdit.inc:8492` 的 `Point_InsertPlane`、`Point_IntersectLayer:8525`、`Geometry_AddCylinder`；`Units/FreeSubdivisionLayer.inc:718` 的 `CalculateIntersectionPoints`；`FreeShip-MCP/engine/HeadlessModel.pas` 的 `measure_section`。来源 U12、U13、I05、I06、I11。

## O11　工况、重心与等排水量倾斜水线　P2

当前有横稳性、KN/GZ 和平衡求解，并非没有稳性计算。可改进的是统一装载质量、重心基准、密度、横倾、纵倾与自由纵倾的输入说明，将不同工况放在同一份可追踪报告中，并明确哪些量已经计算、哪些尚未定义。

GH-77/U26 的等排水量倾斜水线是视图工作流需求：先按给定排水量和工况求平衡，再显示水面，保持原船体不变。不要靠旋转或复制船体凑视觉效果而悄悄改变质量。分舱破损、液舱自由液面等扩展需要另定算法和验证，不能把现有静水力表直接称为完整适航或审批报告。

位置：`Forms/FreeCrosscurvesDlg.pas` 的 `ToolButton1Click:495`；`Units/FreeHydrostaticCalc.inc` 的 `Balance`、`FGetWlPlane`；`Units/FreeProjectSettings.inc`。来源 I07、U12、U21、U26、GH-77。

## O12　阻力方法与外部计算能力清单　P2

保留各方法已经存在的范围提示，统一显示方法名、单位、适用船型、参数范围、数据来源和依赖程序。缺少 EXE、架构不兼容、未收敛、无有效输出要分别报告，不能只给“计算失败”。用固定工况和独立参考结果验证，再考虑原生替代旧二进制。

## O14　发行、跨平台和自动化验证　P2/P3

上游 `.github` 当前只有资助配置，未看到随仓库维护的构建工作流。明确编译器、widgetset、依赖和资源清单，检查干净环境构建、普通用户权限、中文/俄文路径、现代 Linux 依赖及资源迁移。Mac fork 可以作为参考，性能和质量需独立验证。AppImage/Flatpak 属于可选发行方式，本次只记录需求，不制作安装或便携包。

高 DPI、缩放、窄窗口、键盘焦点和原生对话框要独立验收。已有多尺寸图标与原生保存对话框，不能照搬“没有 HiDPI 支持”或“保存按钮一定消失”的说法。安装来源、版本、校验值和帮助入口应清楚可查；第三方下载夹带软件的历史指控不归给上游。

本项目已经有 MCP 和隔离 UI 测试，后续应让它们与桌面源码版本对应，补稳定错误码、批处理进度、取消、故障注入和跨格式样例。物理鼠标、焦点、显示器等未覆盖部分保留明确状态，不用桌面操作工具代替用户验收。地区数字与旧编码的测试应覆盖保存、读回、导出三步，已有修复不再登记为缺陷。

# 加载失败会清空当前模型

状态：已修复（读取和重建失败回归通过，桌面操作未验收）。优先级：P1。

`LoadProject` 一开始就清空现有模型，再读取新文件。新文件解析失败时，没有原模型可回退。另外，文件标识不对时只弹出提示，后面仍会设置 `ModelIsLoaded := True`，让加载失败走到成功状态。

新文件应先读入临时模型，检查通过后再替换当前项目。失败时保留原模型、文件名、修改状态和撤销历史；非法文件应明确终止加载。

代码位置：`Units/FreeShip.inc`，`TFreeShip.LoadProject`。见[加载前清空](https://github.com/markmal/freeship-plus-in-lazarus/blob/1de17e99fb2b1cc559cdf27c5cafb595a627a641/Units/FreeShip.inc#L2042-L2066)、[非法文件提示后仍设置成功状态](https://github.com/markmal/freeship-plus-in-lazarus/blob/1de17e99fb2b1cc559cdf27c5cafb595a627a641/Units/FreeShip.inc#L2228-L2243)。

原始检查（修复前）：已核对源码，未在桌面复现。修复时分别用不存在、截断、标识错误的文件检查，确认失败后旧项目和重做记录都还在。

## 本项目修复（2026-10-30）

`LoadProject` 先在独立候选模型中解析并重建，成功后才交接。文件不存在、标识不对、版本不支持、内容截断或重建抛异常，都不会清理当前模型。交接保留主程序的事件订阅，重新绑定项目对象的归属，并清除点编辑器的旧引用。

同时修正 `FreeEdit.inc` 的两个 `File_Load` 入口和 `Forms/Main.pas` 的打开入口：读取前不再清模型、选择和撤销；成功后才更新文件名、只读状态、最近文件和撤销历史。界面刷新在文件提交后执行，刷新异常不会被误报为解析失败。

测试检查失败前后模型字节、对象身份、选择、文件状态和实际撤销/重做；正常文件检查多次加载、点编辑器、事件订阅和保存往返。见[加载报告](../../../FreeShip-Tests/reports/file-safety-final-20261030-2/report.json)。样本及未覆盖范围见[第一批修复记录](第一批修复-文件安全.md)。本次为本地修改，尚未创建 Git 提交。

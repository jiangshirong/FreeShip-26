# 损坏模型缺少边界检查

状态：已修复，验证范围见下文及第二批总记录。优先级：P1。

以下问题描述为修复前核对，修改进展见文末。

模型内嵌 JPEG 的读取直接采用文件中给出的长度，分配内存并复制，没有先检查剩余字节是否足够。面的控点索引也未经完整验证就用于取值，`-1` 还会被改成 `0`。底层列表越界时既不抛异常，也没有明确设置返回值。

这些路径遇到损坏文件时，可能产生异常内存分配、越界读取或错误的点面连接。读取长度、元素数量和引用索引应统一检查；特殊索引按文件版本解释，不能直接当成正常控点。发现问题就停止加载，并指出出错字段。

代码位置：

- `Units/FreeFileBuffer.pas`，[`TFreeFileBuffer.LoadTJPEGImage`](https://github.com/markmal/freeship-plus-in-lazarus/blob/1de17e99fb2b1cc559cdf27c5cafb595a627a641/Units/FreeFileBuffer.pas#L334-L349)。
- `Units/FreeSubdivisionControlFace.inc`，[`TFreeSubdivisionControlFace.LoadBinary`](https://github.com/markmal/freeship-plus-in-lazarus/blob/1de17e99fb2b1cc559cdf27c5cafb595a627a641/Units/FreeSubdivisionControlFace.inc#L1232-L1254)。
- `Units/FasterList.pas`，[`TFasterList.FGet`](https://github.com/markmal/freeship-plus-in-lazarus/blob/1de17e99fb2b1cc559cdf27c5cafb595a627a641/Units/FasterList.pas#L523-L530)。

已核对源码，未构造损坏文件复现；这里不认定存在已验证的可利用安全漏洞。修复时用截断数据、过大长度和非法索引检查，正常旧格式也要保留兼容性。

## 第一批进展（2026-10-30）

已补 JPEG、字符串和固定记录的剩余字节检查，以及部分集合数量、活动图层索引检查。截断失败时，正在读取的对象由候选模型持有并清理。JPEG 负长度、极大长度和截断数据已纳入[低层测试](../../../FreeShip-Tests/reports/buffer-safety-ftm-final-20261030/report.json)。

面的控点索引、边和曲线的引用、`FasterList` 越界行为尚未完整修复，本条不标为完成。正常旧文件的兼容性还需要扩大样本，不能把这一批测试当成全部损坏文件都能安全拒绝的证明。

## 第二批修复（2026-10-30）

继续补齐这条记录涉及的引用检查。`FreeGeometry.pas` 的 `RequireModelIndex`、`LoadModelCount` 统一检查索引和数量；面、边、曲线、点组先读全并校验，再挂接对象，不再把无效控点 `-1` 当成第 0 点。图层 `-1` 保留为写入器已有的“使用默认层”约定。

`FreeShip.inc` 的名称、锚点、约束和点组读取也加了检查；`FasterList.pas/TFasterList.FGet` 越界时明确抛出 `EListError`。点组写入数量改为与实际写出的组一致，避免匿名组让后续字段错位。

入口：`python -B FreeShip-Tests/file_safety.py --case geometry`。检查负数、过大索引和数量、FBM/FTM、默认图层约定，以及命名/匿名点组后接锚点的完整往返。未穷尽所有旧格式、内存耗尽和恶意输入；不据此宣称整个解析器已达到全面安全性证明。最终源码及报告由第二批总记录统一归档。

最终验证、剩余范围与程序更新见[第二批修复记录](第二批修复-计算与异常处理.md)。

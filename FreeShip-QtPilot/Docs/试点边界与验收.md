# 型线图试点边界

## 原版基准

桥接构建时将当前工作树的 Forms、Units、Packages、Cursors、locale、Themes、Languages 与项目配置打包为 `legacy-source.zip`，保留原文件头与许可证。报告记录原源码、适配器、测试代码、模型及可执行文件的 SHA-256。当前安装程序另存为 `legacy-installed.exe`，只保留作参考，不用它冒充当前源码的构建。

桥接不直接改产品代码。`bridge/build_bridge.py` 在临时构建目录内选择两种入口：生产入口使用 `FreeLinesplanScene.pas`；对照入口使用测试程序中的 `QtLegacyBridge.pas`，在旧窗口流程中插入观测调用。重要锚点或来源哈希不匹配时停止构建。生产构建跳过模型构造函数中两个编辑对话框及日志组件的异常窗口，异常通过进程失败返回。

`PilotCapture.pas` 输出投影后的模型空间坐标，输出点位于原版整数屏幕/图集舍入之前。`extract_scene.py` 保存拆分步骤，`scene-origin.json` 标记对应的原代码版本。标注锚点保留原版拟合视图计算和像素舍入；它不用于几何计算或导出。

测试检查采集前后原版图像是否逐像素一致，防止观测代码改变绘制。另有 Qt 双精度数据往返、独立逐图元绘制、无裁剪全场景绘制对照。不同绘图后端的边缘光栅化可以不同，内部颜色差异不得掩盖为抗锯齿差异。

## FSLP0001 格式

全部数值为小端。8 字节 ASCII 标识后是四个 Float64：minX、minY、maxX、maxY。之后连续记录直到文件结束。

每条记录：UInt32 类型、UInt32 Windows RGB 颜色、UInt32 点数，随后每点两个 Float64。

- 类型 1：填色三角形，严格三个点，顺序就是遮挡绘制顺序。
- 类型 2：折线，至少两个点，不做简化、拟合或重采样。
- 类型 3：标注，一个锚点；后接 UInt32 像素字高、UInt32 UTF-8 字节数和文本。

读取限制总文件大小、点数、标注长度，拒绝非有限数、非法类型及截断数据。不认识的新格式必须拒绝，不能默默按旧结构解释。当前格式没有图层交互、曲线解析式、局部更新 ID，也没有作为自动磁盘缓存的身份头。

## 已建立的验收场景

1. 原始 FBM、测试源码与正式程序保持不变。
2. 基础模型、曲面模型、9a 实际模型分别保存基准；原模型和移动一个未锁定控制点 Z+0.01 的副本都测试。
3. 完整场景坐标及标注经过 C++ 读取、写出后字节相同。
4. 放大 30 倍、平移、恢复后图像不丢填色；有裁剪与无裁剪绘制一致。放大锚点必须来自实际填色，不能用空白视野通过检查。
5. 合成右键事件产生对应平移量，滚轮事件以锚点缩放；真实桌面输入另列 not_run。
6. 100% 与 150% 图像渲染，检查标注重叠、填色切换和还原。
7. GPU/批处理与独立 CPU 逐图元绘制比较；记录边缘差异与纯色内部差异。
8. 独立生成的完整场景与旧入口、历史报告逐字节对照。DXF 同时记录字节比较与完整实体比较：坐标、顶点连接、图层、颜色不设容差；旧程序按指针排序造成的实体排列、遍历方向差异单列 review。截断、坏标识及恶意点数被拒绝。
9. 分别记录读取、整理、GPU 初始化、首帧和连续平移/缩放耗时。离屏耗时含 GPU 读回，不是显示器帧率。

## 需要继续验证的地方

- 原版 `DrawSpline` 的平面图投影使用 `FPlanOrigin.X + YSign * P.Y`，而 DXF `AddSpline` 使用 `FPlanOrigin.X + Points[I].X`。这是两条路径的明确差异；本次采集保留原屏幕行为，不能拿它证明船舶几何正确。修正前应针对水线建立独立几何预期。
- 新标注布局优先放置名称，拥挤时隐藏部分数字。实际阅读、引线和边缘裁切仍需人工检查。
- GPU 驱动冷启动、中文字体首次使用仍有一次性成本。旧窗口准备及重复绘制已移除；新报告分别记录桥接进程、解析、整理、GPU 初始化、首张离屏图像和测试导出耗时。
- 控制点编辑、原生增量 ID、持久缓存失效、窗口间数据同步和多显卡覆盖不在本轮实现范围。

用户已反馈第一轮交互顺滑；场景生成入口随后从旧窗口中拆出。下一步可据测量结果继续处理初始化成本及设计增量接口，仍不据此直接启动整个程序重写。

# 现有工作如何继续使用

这次只增加同级 FreeShip-QtPilot，没有迁移或删除正式程序的窗口。Win+R 的 fs 仍指向 Lazarus 版本。

| 原有维护内容 | 试点中的对应位置 | 保留的要求 |
|---|---|---|
| 型线图窗口、鼠标交互 | src/main.cpp、src/view.cpp | 右键平移、鼠标位置缩放、完整填色、清晰文字 |
| 型线图生成及填色顺序 | bridge/FreeLinesplanScene.pas 的 Generate；PilotBridge.pas 负责加载 | 原浮点类型、原采样、原排序、原遮挡顺序 |
| 场景数据与显示缓存 | src/scene.h、src/scene.cpp、src/gpu_fill.cpp | 数据与相机分开；平移缩放不重新求交、不重传模型 |
| 中文界面与标注 | Qt 界面字符串；桥接输出原中文标注 | 术语与内容继续沿用；字形和布局单独复核 |
| 图片与 DXF 导出 | src/main.cpp | 图片写入用户所选路径；DXF 保留原核心结果 |
| 测试程序 | FreeShip-Tests/qt_linesplan_pilot.py、qt/linesplan_tests.cpp | 相同模型、已知复现步骤、明确断言与未覆盖范围 |

Pascal 控件类、旧窗口句柄、旧行号只适用于旧实现。问题描述、模型样本、预期结果、语言术语、失败证据和验收标准继续适用。新增测试仍归入 FreeShip-Tests，不另外建立一套人工测试界面。

当前 Scene 格式没有增量实体 ID。其他对话暂时不要假定它已经支持局部控制点更新、跨窗口共享模型或自动磁盘缓存。图层选择、灯光、镜像、打印和撤销也尚未迁移到试点 UI。

生产桥接已不调用 `PrepareForDisplay` 或 `ViewportRedraw`。旧流程只在 `FreeShip-Tests/QtLegacyBridge.pas` 中保留为测试对照。`bridge/extract_scene.py` 记录独立入口如何从原算法拆出；原相关文件变化时，来源哈希会阻止继续使用旧提取结果，应先审查变化，再重新提取和运行全套对照。不要通过更新基准跳过几何差异。

# 切换单位后交线位置未换算

状态：已修复，验证范围见下文及第二批总记录。优先级：P1。

以下问题描述为修复前核对，修改进展见文末。

切换项目单位会调用 `Model_Scale` 缩放船体，但函数中同步缩放横剖线、水线和纵剖线位置的代码被整段注释掉了。后面的重新求交不会补上位置换算。

例如，`x=10 m` 的横剖线改用英尺后应为 `32.8084 ft`。数值仍是 `10`，就成了物理位置 `3.048 m`。船体换了单位，原来的站位却没有跟上。

单位转换应单独处理，完整换算带单位的数据；不要让它直接沿用只改变船体尺寸的流程。这样切换单位后，型线站位仍对应原来的物理位置。

代码位置：`Units/FreeProjectSettings.inc` 的[单位转换调用](https://github.com/markmal/freeship-plus-in-lazarus/blob/1de17e99fb2b1cc559cdf27c5cafb595a627a641/Units/FreeProjectSettings.inc#L274-L298)，以及 `Units/FreeEdit.inc`、`TFreeEdit.Model_Scale` 中[被注释的交线变换](https://github.com/markmal/freeship-plus-in-lazarus/blob/1de17e99fb2b1cc559cdf27c5cafb595a627a641/Units/FreeEdit.inc#L8222-L8230)。

已核对调用关系和换算例子，未在桌面复现。修复时检查三类交线在公制、英制往返后的物理位置。

## 第二批修复（2026-10-30）

在 `FreeProjectSettings.inc/TFreeProjectSettings.FSetProjectUnits` 内完成单位转换专用处理：横剖线、纵剖线、水线和斜剖线的平面距离随长度单位缩放，法向保持不变。吃水范围、步长、纵倾、重心高度、稳性纵倾及排水量列表也转换。`FreeEdit.inc/TFreeEdit.Model_Scale` 保留自定义剖面坐标的正负号；普通几何缩放没有被改成单位转换。

入口：`python -B FreeShip-Tests/units_conversion.py`。检查四类交线的平面和重新计算后的曲线范围、全部控点及锁定点、重复选择同单位、两次公英制往返，以及静水力物理量。测试调用真实设置方法，不只比较换算公式。

同一入口还检查 Kaper/Planing 的手工排水量按质量单位换算，Delft 的容积输入仍按体积换算，详见[密度与质量换算记录](05-英制密度换算存在偏差.md)。另用三个方向分别放大 2、3、4 倍的普通缩放作对照：质量和容积仍乘 24，避免单位修复改变原有的几何缩放行为。

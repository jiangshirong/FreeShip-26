# 板材展开误差量纲与说明

状态：已修复，验证范围见下文及第二批总记录。优先级：P2。2026-10-29 核对。

以下问题描述为修复前核对，修改进展见文末。

展开过程用“二维边长减三维边长”计算边误差，用“二维面积减三维面积”计算面误差。随后把最大边误差与总面积误差的绝对值相加，作为 `MaxError`。两者量纲不同，同一块板换用不同长度单位或缩尺后，相对权重会变化。总面积误差还是有符号累加，局部正负误差可能抵消。

这不直接证明展开结果错误，但评分需要说明和尺度验证。应分别保留长度、面积指标，按模型尺度归一化后再组合；同时报告局部最大值、绝对误差总量和有符号总量。验证平面、圆柱面及有双曲率的面板，并比较单位转换前后的结果。

这个评分还会用于比较不同起始面的展开结果（同文件第 1687–1711 行），因此不只是界面数字的单位问题。归一化后，同一块板换单位时不应仅因权重改变而选出不同方案；是否已经影响具体板材，需要样例测量。

界面当前直接显示这些数值，没有在同一处给出完整的长度/面积单位及正负号解释。应补充图例，并说明可展性着色、展开误差和材料可加工条件的区别，避免把零边误差当成整块板可以无误差制造。

代码：`Units/FreeDevelopedPatch.inc`，`Unroll` 内 `ProcessFaces`，第 1534–1577 行；`Forms/FreeExpanedPlatesDlg.pas`，`FSetActivePatch` 第 307–310 行。见[上游评分计算](https://github.com/markmal/freeship-plus-in-lazarus/blob/1de17e99fb2b1cc559cdf27c5cafb595a627a641/Units/FreeDevelopedPatch.inc#L1534-L1577)。

来源：[U03](https://www.boatdesign.net/threads/freeship-negative-area-error-on-developed-plates.69791/)、U15、U16、U19。已核对公式与当前显示代码，未运行原帖模型。面积误差的单位应为面积单位，不能沿用论坛回复中把它说成米的解释。

## 第二批修复（2026-10-30）

进一步核对发现，`FreeDevelopedPatch.inc/Unroll` 的二维 `TriangleArea` 也写错了：原式是边坐标差乘积的和，并非三角形面积。现改为二维叉积绝对值的一半。用隔离副本恢复旧公式，普通 3×3 平面也会出现虚假的面积和边长误差；这能证明该公式有问题，但不等于复现了原帖模型。

展开方案评分改为 `最大绝对边差/√三维总面积 + 各面面积差绝对值之和/三维总面积`。两项均无量纲，局部正负面积误差不再抵消。保留原边长差、有符号总面积差和局部最大面积差，另记录绝对面积差总量。镜像复制同步保留这些指标。

`FreeExpanedPlatesDlg.pas/FSetActivePatch` 给原四个数值附长度或面积单位；提示说明正负号、绝对差总量及评分，并说明这些几何误差不是材料加工允差。中文提示同步加入词条。

入口：`python -B FreeShip-Tests/plate_errors.py`。实际展开平面、倾斜平面、多折面圆柱和鞍面，比较原尺寸、英尺倍率和两倍尺寸的面积、评分及全部二维点对距离。`--mutation legacy-area`、`--mutation legacy-score` 可在隔离副本恢复两种旧错误，检查测试能否识别。

没有验证任意网格、极端缩尺、材料成形和真实桌面显示；面积误差接近零不代表可以直接制造。最终源码及报告由第二批总记录统一归档。

最终验证、剩余范围与程序更新见[第二批修复记录](第二批修复-计算与异常处理.md)。

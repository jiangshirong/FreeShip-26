### 旧 FBM 文件的兼容性：P1，已发现失败样例，原因待定位

[#111](https://github.com/markmal/freeship-plus-in-lazarus/issues/111) 报告自带的 `Motorboat3.fbm` 打不开。作者只回复会检查；另一位开发者在 [PR #124](https://github.com/markmal/freeship-plus-in-lazarus/pull/124) 提出版本枚举宽度和记录内存对齐导致错位的解释。核对时该 PR 尚未合并，其测试结果是提交者的陈述。

本地现有 MCP 引擎读取 `Ships/Database/Motorboat3.fbm` 时返回 `Exception: Truncated model record`；同一引擎能够读取 `Ships/board.fbm`。这是 MCP 的读取结果，不是桌面加载复现。

还用 `ppudump` 检查了现有桌面编译产物 `lib/x86_64-win64/FreeVersionUnit.ppu`，版本枚举大小为 1 字节。两份样例的文件头也都可按 1 字节版本号、4 字节精度字段解释。因此不能直接套用“当前程序必定把 1 字节版本号读成 4 字节”的说法。

代码中仍存在按 `SizeOf(Output)` 读取版本、逐字段读取后又跳到 `bp + sizeof(Data)` 的做法。后续应逐字段追踪失败位置，按明确的磁盘格式处理各版本，保留必要的历史填充字节，不能直接删掉所有对齐处理。

代码：`Units/FreeFileBuffer.pas`，[`LoadTFreeFileVersion`](https://github.com/markmal/freeship-plus-in-lazarus/blob/1de17e99fb2b1cc559cdf27c5cafb595a627a641/Units/FreeFileBuffer.pas#L1953-L1965)、[`LoadTFreeDelftSeriesResistanceData`](https://github.com/markmal/freeship-plus-in-lazarus/blob/1de17e99fb2b1cc559cdf27c5cafb595a627a641/Units/FreeFileBuffer.pas#L375-L404)。样例 SHA-256：`6f0e9d13fdc15f80339823303897e20c9dbbc019f3443ebb239f172671516adf`。

### 提取船体数据也可能写文件：P1，路径已确认，具体报错原因待复现

[#126](https://github.com/markmal/freeship-plus-in-lazarus/issues/126) 报告在多体船阻力窗口勾选“从当前船体提取数据”后出现访问拒绝，核对时没有作者回复。

本地该入口会调用静水力计算，默认计算项为 `hcAll`。满足 Bonjean/SAC 条件时，计算核心会向当前工作目录写 `SACs.txt`、`Bonjean.txt`。这是一条实际存在的写盘路径，但还不能认定它就是该报告的唯一原因。

纯计算应返回数据，写报告由显式导出操作处理。需要中间文件时，使用本次任务独立的可写目录，并处理写入失败。

代码：`Forms/FreeResistance_MHDlg.pas`，`DraftTotalBoxAfterSetValue`；`Units/FreeHydrostaticCalc.inc`，[`SACs.txt` 写入分支](https://github.com/markmal/freeship-plus-in-lazarus/blob/1de17e99fb2b1cc559cdf27c5cafb595a627a641/Units/FreeHydrostaticCalc.inc#L1955-L1975)。

### 非对称部件的 STL 导出：P1，已核对源码

核查导出相关讨论时，另外发现 STL 路径无条件镜像，不读取图层的对称设置。单独记录在 [13-STL导出忽略图层对称设置](13-STL导出忽略图层对称设置.md)。

### OBJ 导入后的船型是否保真：P2，需要样例对照

[#120 的作者回复](https://github.com/markmal/freeship-plus-in-lazarus/issues/120#issuecomment-2741739249) 解释，全部设为硬边有保持输入网格形状的考虑：把原网格直接作为细分控制网，解除硬边后，最终表面会收缩。真正的光顺导入需要考虑如何反求控制网。

本地 `ImportObjFile` 主要读取顶点和面，没有读取 OBJ 平滑组、法线等信息。优化应提供明确的导入方式，并比较导入前后的尺寸和表面偏差，不能简单把边全部改成光顺就算修好。其他程序的“锐边”也不一定按同一规则写进 OBJ。

代码：`Units/FreeSubdivisionSurface.inc`，[`TFreeSubdivisionSurface.ImportObjFile`](https://github.com/markmal/freeship-plus-in-lazarus/blob/1de17e99fb2b1cc559cdf27c5cafb595a627a641/Units/FreeSubdivisionSurface.inc#L2609-L2668)。

### STL/OBJ 的输出单位与缩尺：P2，属于互操作改进

[#121](https://github.com/markmal/freeship-plus-in-lazarus/issues/121) 报告 STL 进入切片软件后尺寸缩小。作者指出 STL 本身不保存单位，现有输出沿用项目单位，并表示可以增加单位选择。

这不能写成“STL 标准规定必须用毫米，而上游违反标准”。实际可改的是在导出时明确选择米、毫米或缩尺，显示导出后的包围盒尺寸，并让网格精度与用途匹配。当前 `File_ExportSTL` 直接写模型坐标，没有这一步选择。

### 外部计算模块的维护边界：P2，超过了启动超时问题

[#96 的作者回复](https://github.com/markmal/freeship-plus-in-lazarus/issues/96#issuecomment-1368580141) 说明，一些辅助计算程序是没有随主程序提供源码的旧二进制模块。作者也提出，理想做法是按原始论文原生实现，但需要专业知识和较大工作量。

发布前应列清每个功能依赖哪个程序、是否可用、依据什么方法。需要替代时逐项建立对照算例；不能把整个计算链都当成可随主程序源码一起维护的部分。这不等于已经认定这些模块的许可有问题。

### 导出格式与地区设置：P2，先做回归验证

[#91](https://github.com/markmal/freeship-plus-in-lazarus/issues/91) 报告 IGES 中混入逗号小数，作者确认过地区设置可能参与数字写出。

当前 `FloatToDec` 已使用独立格式设置并固定小数点；IGES 保存也设置了小数点。因此，这条历史反馈不能直接作为当前仍会输出错误 IGES 的证据。后续应覆盖逗号小数地区、不同界面语言和独立 CAD 重新读取；写文件尽量使用局部格式设置，不改变全局设置。

代码：`Units/FreeGometry_Functions.inc` 的 `FloatToDec`；`Units/FreeIGESUnit.pas` 的 `SaveToFile`。

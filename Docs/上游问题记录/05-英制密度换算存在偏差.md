# 英制密度换算存在偏差

状态：已修复，验证范围见下文及第二批总记录。优先级：P1。

以下问题描述为修复前核对，修改进展见文末。

代码以 `Lbs = 0.44642857` 推导密度换算系数，但磅的标准质量是 `0.45359237 kg`，界面中的英制密度单位也是 `lb/ft³`。按现有公式，`1.025 t/m³` 会换成约 `65.01548 lb/ft³`，标准换算约为 `63.98866 lb/ft³`，偏差约 1.60469%。

应把长度、密度、公吨和长吨分别换算，集中维护常数，并检查同一模型切换单位前后的物理量是否一致。历史英制文件需要核查密度来源，不能一律自动改值。

代码位置：`Units/FreeGeometry.pas` 的[换算常数](https://github.com/markmal/freeship-plus-in-lazarus/blob/1de17e99fb2b1cc559cdf27c5cafb595a627a641/Units/FreeGeometry.pas#L100-L103)，以及 `Units/FreeProjectSettings.inc` 的[`FSetProjectUnits`](https://github.com/markmal/freeship-plus-in-lazarus/blob/1de17e99fb2b1cc559cdf27c5cafb595a627a641/Units/FreeProjectSettings.inc#L262-L298)。密度单位见 [`DensityStr`](https://github.com/markmal/freeship-plus-in-lazarus/blob/1de17e99fb2b1cc559cdf27c5cafb595a627a641/Units/FreeGometry_Functions.inc#L103-L109)。

上述数值已按源码公式独立核算，尚未完成桌面单位切换对照。修复后应比较密度、几何容积和统一为公吨后的排水量。

## 第二批修复（2026-10-30）

`FreeGeometry.pas` 用标准磅质量 `0.45359237 kg` 推导密度换算，并把密度系数与公吨/长吨系数分开。`FreeProjectSettings.inc/TFreeProjectSettings.FSetProjectUnits` 同步换算水密度、材料密度及板厚。保留 `Lbs` 兼容别名；使用该质量常数的力换算同步修正，但未改变原重力加速度约定。

复查时还发现，`FreeEdit.inc/TFreeEdit.Model_Scale` 把 Kaper 和 Planing 保存的排水量也乘了长度换算系数的三次方。这两个字段存的是质量，Delft 等模块中的同名字段才是容积。现在单位切换后，这两个质量输入按公吨/长吨换算；普通改变船体尺寸时，仍保留原来的体积比例缩放。读取已有文件不改写这些输入。

入口：`python -B FreeShip-Tests/units_conversion.py`。通过真实单位设置入口检查 `1.025 t/m³` 的换算、公英制往返、几何容积和统一吨位后的排水量、图层面积及质量。历史英制文件里的密度按原值读写，不猜测来源并自动改数。

手工输入测试关闭 Kaper/Planing 的自动提取，检查两次公英制往返，并执行实际阻力命令到窗体初始化，核对输入框收到的排水量。测试在计算和显示窗口前停止，没有验证这两个阻力算法。`--mutation old-resistance-mass` 只在隔离副本恢复旧换算，用于确认测试能抓住这个错误。

尚未验证每个历史模型和外部计算程序的全部输入，也未做桌面交互验收。最终源码及报告由第二批总记录统一归档。

最终验证、剩余范围与程序更新见[第二批修复记录](第二批修复-计算与异常处理.md)。

# Archimedes 与 PAM 输出

文件菜单新增 ArchimedesMB（`.hll`）、Archimedes 单体（`.app`）和 PAM 旧版几何
模板（`.pam`）。几何求交、离散、单位换算和文件生成在 C++ 完成；不调用旧导出
对话框。读取 FBM、维护文档和编辑历史仍由当前桥接核心负责。

## 几何范围

三种格式与 GHS 共用 `src/core/hull_sections.cpp`。使用工程现有横剖站和全部
静水力图层，包括隐藏图层。当前入口支持对称半船，不按相机裁切，不自动补站。
敞开甲板只有明确勾选才水平封到中心线；不填补船底或横向缺口。

保留原型值点和折角，曲线离散弦误差为 0.1 mm。这个界限只针对继承的三次
样条转折线，不代表曲面建模、纵向站距或整体排水量误差。超出安全预算会停止，
不会减少点数凑出文件。非对称、跨中心线控制网和自交也会停止导出。

上下分离、收于中心线且高度范围不重叠的轮廓沿中心线连接。连接不增加面积或
一阶矩；Archimedes 输出镜像后的完整轮廓，PAM 使用半船。闭合中心面在镜像后
成为内部面，完整外轮廓不再重复末尾向下的中心线段。分离轮廓的接收程序兼容性
仍待验证，不能据此声称已完成多附体模型划分。

## 单位与参考位置

输出固定使用米。英制模型的坐标和尺度乘 `0.3048`，水密度从 lb/ft³ 换回
t/m³，PAM 再换成 kg/m³。转换只作用于输出副本，不改变工程单位。

Archimedes 的纵向 Y 对应 FreeShip 的 X，横向 X 对应 FreeShip 的 Y，垂向 Z
保留原高度。HLL 为 UTF-8 XML，名称正常转义；APP 的说明字段沿用 ASCII，
不能表示的字符用 `?`，中文路径和空格仍原样保留。

窗口允许填写 AP、FP，以及 HLL 的艉、中、艏吃水标志纵向位置，全部以米表示。
默认 AP=0、FP=船长，标志在两端和中点；这只是初始值，应按工程实际位置填写。
它们是参考标志位置，不是水面高度，也不会移动输出几何。

原作者 John A. MacSween 的 [2006 年手册](https://manualzilla.com/doc/5779041/archimedesmb-user-manual)
第 24、32–35 页说明了坐标方向、米制和吃水标志的纵向含义，并要求剖面不交叉。
链接为原作者手册的镜像；文件字段顺序另对照 Plus 源码，未取得接收软件验证。

PAM 的纵向为 `中船位置 - X`，垂向为 `Z - 设计水线Z`，横向为正半宽。
默认中船位置为船长的一半，水线取当前模型的实际设计水线；两项均可修改。
不会先按已选断面的最低点平移，避免横剖站未经过最低点时改变吃水。

## 对照旧代码发现的问题

- `Units/FreeEdit.inc::File_ExportArchimedes`：旧 HLL 的 XML 声明前多一个空格，
  项目名直接拼进标签，遇到 `&` 或 `<` 就不是合法 XML。新输出使用 XML 写入器，
  中文和转义字符做了独立读取测试；XML 不接受的控制字符会明确报错。
- 同一函数将 `FWD_DRAUGHT_MARK`、`MID_DRAUGHT_MARK`、`AFT_DRAUGHT_MARK` 全写成
  `ProjectDraft`，与原作者说明的纵向位置不符。新窗口明确显示和写出实际位置。
  旧输出也没有将英制尺度和密度转到此处采用的米制约定。
- `File_ExportPAM` 将英制尺度乘 `1/Foot`，而 `FreeGeometry.pas` 的 `Foot=0.3048`。
  在米制模板中这会把换算方向写反。新输出按英尺到米换算，另验负基线和水线位置。
- 旧 PAM 将复杂断面改为 10 个均匀参数点加折角，文件名还会删掉空格。新入口
  保留精度控制下的完整断面，按用户所选路径提交。

这些条目描述固定旧版源码的行为，不把本轮迁移问题记成上游错误。具体位置可按
上述函数名定位。旧源码和已有“上游问题记录”目录作为基准未被修改。

## PAM 的范围限制

PAM 暂按旧 Windows 输出的记录结构提供几何模板。第二行尾部的
`1600 100 .2 2. 1000 0`、十个零和站表参数 `1. 0.` 原样保留，结束标记固定为
`\*`，不再随当前系统的目录分隔符变化。

目前没有找到这些计算参数的完整原始规范，也没有取得相应接收程序。窗口明确
要求按接收程序核对参数，不解释或擅改这些常数，不声称模板直接产生可靠计算
结果。它与 `Add_Mass.EXE` 的 `INA.` 输入是不同入口；后者尚未迁移。

## 事务与验证

`FreeShipGeometryExport.exe` 在私有目录生成文件，核对文档身份、版本和输入单位。
Qt 收到成功报告后再次核对文档版本与 SHA-256，才原子替换目标。取消、失败、
超时均不提交文件。对话框沿用 StudioLight，计算期间仍能关闭取消。

统一测试入口为 `qt-ship-formats`，源码在 `FreeShip-Tests`。独立 XML/文本读取器
核对声明数量、顺序、坐标和结束标记；解析箱体核对面积、重心和体积。另测英制、
负基线、参考位置、中心面、上下分离轮廓、名称转义、拒绝路径与原文件保护。
三个真实样本经过实际 Qt 菜单回调；无横剖站模型明确拒绝，9a 导出 11 个站，
HLL/APP 各 4,331 个点，PAM 为 2,171 个点。编辑后更新、撤销还原、取消、场景
和 DXF 不变分别检查。旧 GHS 输出另作回归，9a 文件与上轮逐字节一致。

隐藏 Windows 窗口的截图已查看；真实桌面、系统文件选择器、Archimedes/PAM
接收程序仍未验收。报告分别保留 review / not_run，不能把自有读取器通过称为
外部软件认证。测试源码、失败记录和输出位置见交付记录。

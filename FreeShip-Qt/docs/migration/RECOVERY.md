# 未保存船模的恢复

2026-11-04。对应功能清单中的恢复快照和上游改进方向 O01。

每次模型修改提交后，文档服务直接把当时的完整 FBM 数据写入恢复副本。
不重新生成曲面、剖面或型线图，也不写原船模。一个正在编辑的文档只保留一份最新副本；
平移、缩放和只读计算不会产生一串历史文件。恢复目录是 Qt 的本地应用数据目录下的 `recovery`。

无参数启动时，若发现遗留副本，显示“恢复未保存的船模”窗口。可以恢复一份、
稍后处理，或经确认删除所选副本。文件菜单保留同一入口。用文件路径启动时，
优先打开指定文件，遗留副本继续保留。正在其他窗口编辑的文档不会列入恢复列表。

恢复的船模保持“未保存”状态，保存时需要选文件名；已有原文件不会被自动覆盖。
原文件名仅用于提示和建议另存为名称。恢复不会把临时文件加入最近打开列表。

保存到用户目标并收到保存确认后，才清理对应恢复副本。撤销到保存点也会清理，
重做修改会重新生成。关闭时取消操作保留副本，明确放弃修改才删除。
打开另一个船模失败时，当前船模和恢复副本都保留。

副本使用单个原子写入文件保存元数据和 FBM，包含长度、格式版本和 SHA-256 校验。
写入失败保留上一份副本，并在状态栏提示手动保存；不会把已经接受的编辑报告成失败。
恢复时还会经过正常 FBM 解析和模型发布检查。校验失败或解析失败的文件保留在原处。
每份副本有进程锁，不允许两个窗口同时领取。不同窗口编辑同一个原文件仍分别保留副本。

代码入口：

- `src/core/recovery_store.*`：副本格式、原子提交、校验和进程锁。
- `src/document/document_service.cpp`：提交后写副本、保存点清理；使用原本保存所用的 FBM 字节。
- `src/app/model_session.*`：领取副本、恢复为未保存文档、新副本成功后才移除旧副本。
- `src/app/recovery_dialog.*`、`startup.cpp`、`main_window.cpp`：启动提示、文件菜单、关闭和保存流程。

测试入口为 `FreeShip-Tests/run_tests.py --suite qt-recovery --runtime <运行包> --output <测试目录>`。
`qt/recovery_tests.cpp` 保留了跳过析构退出的崩溃生成器及文件占用故障注入；
`qt_recovery.py` 用独立解析器核对 FBM 字节，再走实际 Qt 启动、恢复、删除和关闭回调。
原来的启动、最近文件和保存测试继续保留。

边界：恢复的是最后成功提交的船模，不包含尚未提交的鼠标拖动或参数框输入，
也不持久化撤销历史、相机位置和打开的子窗口。磁盘写入失败期间只能恢复上一份成功副本。
正常文件保存和恢复副本仍不能替代用户自己的备份。真实桌面输入和电源中断未模拟，
隐藏窗口测试不能算这两项验收通过。

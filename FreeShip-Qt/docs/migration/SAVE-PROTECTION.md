# 保存备份与覆盖冲突

## 2026-11-09：保存确认绑定到实际文件

这次修复的是 Qt 文档服务中的确认缺口。原 `mark_saved` 即使没有对应的待保存结果，
也会把当前历史位置标为已保存。现在保存准备阶段返回一份凭据，包含文档、修订号、
随机标识、完整字节数和 SHA-256。Qt 暂存文件时核对这些内容，后台确认时再核对实际
目标文件；凭据与文件不匹配、已经换了文档或修改了模型，都不能清除未保存标记。

目标已写好但确认回复丢失时，Qt 使用同一凭据和请求号自动重试，最多两次、间隔三秒。
后台重复确认不会再次写文件，不会轮换 `.Bak`，也不会新增撤销记录。
迟到的重复回复不覆盖新操作的状态。新一次保存准备取代旧凭据；普通查看操作和被拒绝的
过期命令不撤销仍然有效的准备。

目标文件在确认前被改动、删除或变成目录时，拒绝确认，保留当前修改、撤销和恢复副本。
后台直接退出仍走已有的中断提示与重新打开流程，不以自动回复重试冒充进程恢复。
本轮没有为后台撤销历史建立跨崩溃的持久事务日志。

新增测试 `FreeShip-Tests/qt_save_confirmation.py` 已接入 `qt-save-protection`，包括伪造、
缺失、过期、跨文档、被替代和重复凭据，以及实际目标文件缺失、被改写和路径不一致。
`qt/save_protection_tests.cpp` 在自身拥有的真实子进程通信中丢弃两次成功确认，验证第三次
确认成功、备份只产生一次；还测试重复回复与下一次编辑交错、暂存文件被替换，以及
目标写入后确认前被外部改写。

原保存、恢复、预览、文档和编辑回归继续使用原有入口。测试报告、安装版本与保全检查
见 `FreeShip-Tests/maintenance/save-confirmation-delivery-20261109.json`。

## 2026-11-04：备份与覆盖冲突

2026-11-04。Qt 先前只保证单个目标文件的原子替换，没有恢复旧版的 `.Bak`，
也不知道文件是否已被另一个窗口改过。本次补齐这两个缺口，并验证保存确认中断后的恢复。

## 使用行为

- 覆盖 `船模.fbm` 时，原文件内容成为同目录的 `船模.Bak`，只保留一版。
- 另存为并覆盖已有文件时，也备份那个文件原有的内容。保存新文件不产生空备份。
- 当前内容与磁盘文件完全相同时，不重复写入，也不把有用的上一版备份换掉。
- 直接打开 `.Bak` 后编辑保存，其备份名为 `.Bak.Bak`，避免目标与备份指向同一个文件。
- 原文件在打开后被其他窗口修改或删除时，拒绝覆盖；当前编辑、撤销历史和恢复副本保留，
  可以另存为不同文件名。这里不会用文件时间判断内容是否相同。
- 沿用现有保存、另存为和错误提示。成功创建备份后，状态栏显示备份位置。

## 实现位置

`src/core/model_file_save.h/.cpp` 负责路径核对、内容指纹、保存锁、暂存及备份回退。
`src/app/model_session.cpp` 在打开时记录实际载入内容的 SHA-256，保存前携带该版本；
另存为则在请求开始时记录所选目标的版本。保存成功后才采用新版本。

目标和备份共用固定名称的 `QLockFile`，使遵守同一协议的 Qt 窗口不能同时保存。
每次准备和提交均核对目标内容，提交前也检查备份有没有变化。
新目标先写同目录的私有临时目录，再用拒绝覆盖已有文件的重命名安装；
如果保存期间目标名称被占用，保留新出现的文件。

已有目标使用 `QSaveFile`，关闭直接覆盖回退。先准备新船模、上一版备份及旧备份的
保护副本；备份安装成功后再安装船模。如果船模提交失败，恢复旧备份。
如果回退时备份又被外部修改，不覆盖外部内容；保护副本留下，并在错误中给出位置。
退出时先关闭临时文件句柄，再删除临时目录，兼容 Windows 的文件占用规则。

会话仍按“服务生成完整 FBM → Qt 写入目的地 → 服务确认保存点”执行。
目标已写入但确认丢失时，界面保守地保留未保存标记和恢复副本。
本次没有改变 FBM 编码、几何计算或导出算法。

实现依据为 Qt 的 [QSaveFile](https://doc.qt.io/qt-6.8/qsavefile.html)、
[QLockFile](https://doc.qt.io/qt-6.8/qlockfile.html) 和
[QFile::rename](https://doc.qt.io/qt-6.8/qfile.html#rename) 文档。
行为参考当前 Plus `Units/FreeSafeFile.pas` 的备份要求；C++ 保存事务为本项目新实现，
沿用 GPL-2.0-or-later，没有照搬 Windows `ReplaceFileW` 的调用流程。

## 尚未覆盖的边界

保存锁只约束使用同一锁协议的程序。无关程序如果恰好在最后一次内容检查与目标替换之间
写入，仍可能发生竞争；这不是任意进程之间的文件内容比较交换。
目标和 `.Bak` 是两个文件名，不构成跨文件的原子事务；尚未做硬件断电、网络盘中断验收。
已有进程中断和实际文件错误测试不能替代这些情况。完整跨进程两阶段提交也未实现。
隐藏 Qt 生产回调不代替真实桌面鼠标、原生文件选择窗口的验收。

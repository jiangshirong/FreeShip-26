# 控制网与逐级细分迁移复核

复核日期：2026-11-01。本轮审查对象是独立验证目标中的控制网输入、两种细分模式及逐级输出，不是正式程序计算入口的替换。审查只写本文件，没有修改 Plus、候选计算实现、测试代码或已部署程序。

ShipCAD 是可选参考。本轮候选采用当前 Plus 的计算规则重新组织无界面核心，没有把 ShipCAD 当作必须移植的实现。当前 Plus 也只提供兼容性参照：旧、新结果一致与符合独立数学预期，是两项不同的检查。Plus 参照是已含本项目修复的本地工作树，不能称为原封不动的上游发行版。

## 输入边界

“完整控制网”在本轮指已加载、坐标已确定的静态计算输入，不能解释为完整可编辑文档或新的 FBM 读写器。

| 数据 | 必须保留的含义 |
|---|---|
| 控制点 | 输入顺序、Single 坐标及原始 Regular / Crease / Dart / Corner 类型；不能只从显示快照反推 |
| 控制边 | 两个端点、原始折痕标记、所归属的控制曲线；包含无面独立边，不因不参与细分而静默丢弃 |
| 控制面 | 有向顶点环、层索引、根控制面身份；不能将顶点排序后当作同一个有向面 |
| 控制曲线 | 有序控制点链、边归属、显隐；附着曲线与独立曲线分开处理 |
| 图层 | 对称、面/控制网显隐、交线/静水力/型线图开关、可展开标记、颜色/透明度、密度/厚度、名称/编号 |
| 计算设置 | QuadTriangle / CatmullClark 模式、精度元数据、实际请求级别。Plus 的四档精度对应通常请求的 1–4 级，显式 0 级另有意义 |

锁定、约束、锚点、分组、编辑实体名称、撤销历史等仍由原文档持有；本轮是在约束已落实到坐标后作只读细分，没有迁移这些编辑能力。孤立控制点和独立边应另行输出；几何包围盒只统计实际面/曲线引用的点，不等同于旧 `Surface.Min/Max` 的所有历史行为。

这一边界尤其容易被构造测试误改。原 [控制点加载](D:/桌面文件夹/项目/FreeShip_26/FreeShip-Plus-Lazarus/Units/FreeSubdivisionControlPoint.inc:741) 和控制边加载直接读类型/折痕；[Surface.LoadBinary](D:/桌面文件夹/项目/FreeShip_26/FreeShip-Plus-Lazarus/Units/FreeSubdivisionSurface.inc:4266) 最后设 `FInitialized=true`。另走 `AddControlFace`、折痕 setter 或 `Initialize` 会重新调整类型，不能拿调整后的旧结果与未经调整的新输入比较。

## 已核对的活动计算路径

| 环节 | 当前 Plus 的行为 | 审查要求 |
|---|---|---|
| 主循环 | 每轮先处理独立曲线，再增加级别、拆面，最后 `Average` | 不能把类中存在的其他方法自动接入主循环 |
| 最后平均 | `Rebuild` 中 `LastAveraging` 整段已被注释 | 本轮不启用它；否则即使细分拓扑相同，坐标也会变化 |
| 同轮平均 | 先计算所有新坐标，再统一写回 | 不允许逐点原地更新，让后面的点读到前面已平均的邻点 |
| 三角面 | QuadTriangle 拆为四个三角面；CatmullClark 通过面中心拆成三个四边面 | 两种模式都要验证，不能只在纯四边输入上比较 |
| 其他面 | 先算算术面中心，再围绕每个原顶点生成四边子面 | 五边面等输入第一轮处理后，平均阶段只遇到三角/四边面 |
| 顶点 | 先复制坐标与原点类型，组装新邻接，再统一平均 | 不应先套标准顶点公式，随后又做一次旧平均 |
| 边点 | 先取中点；折痕边点标 Crease，其他标 Regular | 光滑内边的后续平均是活动算法的一部分 |
| 折痕/边界 | Crease 点使用自身的 1/2，加每条折痕或单面边另一端的 1/4 | 拓扑边界依据邻面数为 1；不是产品的“漏水边”条件 |
| 三角扇 | 权重包含余弦项的平方；Plus 对价数 1–8 有 Single 常量表 | 要覆盖非平面三角扇及价数超过 8 的运行时分支 |
| 混合邻域 | 三角和四边面使用不同角权重，再按邻面组成算系数 | 不用纯 Loop 或纯 Catmull–Clark 公式代替混合规则 |

位置：[Surface.Rebuild](D:/桌面文件夹/项目/FreeShip_26/FreeShip-Plus-Lazarus/Units/FreeSubdivisionSurface.inc:4591)、[Average](D:/桌面文件夹/项目/FreeShip_26/FreeShip-Plus-Lazarus/Units/FreeSubdivisionSurface.inc:4757)、[Point.Averaging](D:/桌面文件夹/项目/FreeShip_26/FreeShip-Plus-Lazarus/Units/FreeSubdivisionPoint.inc:331)、[Face.Subdivide](D:/桌面文件夹/项目/FreeShip_26/FreeShip-Plus-Lazarus/Units/FreeSubdivisionFace.inc:269)。

`Edge.IsBoundaryEdge` 还检查端点是否离开 y=0 对称面，这是船体边界/漏水判断。把它替代平均公式中的单面边条件，会使对称面附近的几何发生改变。见 [FreeSubdivisionEdge.inc](D:/桌面文件夹/项目/FreeShip_26/FreeShip-Plus-Lazarus/Units/FreeSubdivisionEdge.inc:15)。

## 控制曲线与层对称

[独立曲线判定](D:/桌面文件夹/项目/FreeShip_26/FreeShip-Plus-Lazarus/Units/FreeSubdivisionControlCurve.inc:656) 要求每个控制点都不属于任何面。它不是“曲线边没有面”的同义词。跨接有面点和无面点的曲线，必须明确支持或拒绝，不能只输出其中一段。

[SubdivideFreeStanding](D:/桌面文件夹/项目/FreeShip_26/FreeShip-Plus-Lazarus/Units/FreeSubdivisionControlCurve.inc:857) 的第 0 轮是复制：端点设 Corner，其他非 Corner 点设 Crease，边设折痕；这轮还没有插中点。之后的轮次才插中点，每轮仍参加表面的统一平均。因此请求 1 级和请求 2 级的独立曲线，不能按面细分次数猜测点数。

原过程还会调整原控制点类型和边标志。旧探针必须为每个请求级别重新加载对象，并把请求输入与执行后的有效输入分开记录，避免前一个用例的调整污染后一个。候选的重复请求、倒序请求和从高一级再取低一级，也要得到相同的已定义结果。

这里验证的是同一份静态输入，不是所有旧文档调用历史。特别是多条独立曲线共享点时，旧对象完成一次重建后可能已改变下次重建的输入类型；不能由 fresh 对照通过推导旧同一对象的所有调用序列都等价。候选保留不可变输入的设计合理，但将来接入控制曲线编辑流程时仍需单独验证这一接缝。

附着曲线应沿实际顶点和边的后代更新有序点链；不可拿细分后按坐标排序的点重新拼线。主流程最后调用 `RebuildSpline`，其折角由 Corner 决定，不能擅自换成另一个 `ControlCurve.Rebuild` 中的额外判据。这里验证点链与折角，不代表已验证完整切割和交线生成。

层的对称标记不参加本轮 `Subdivide/Average`，应按原值传递，不自动复制镜像半船。隐藏层及不参加交线/静水力的层仍保留计算控制网；其筛选语义在后续相应计算中处理。

## 拓扑与顺序

子面要保留根控制面、子面次序、所属层及有向顶点环。原四边子面的起始顶点随角序循环移动；把每个面都旋转成“原顶点在第 0 位”虽然不改抽象拓扑，却会改变下一轮 Single 加法顺序。面朝向、共享边、邻面列表、折痕继承、曲线归属都需逐项比较，点数/面数相等不足以证明对应关系。

原内部若干引用表按指针排序用于查找。地址不是稳定几何身份；输出可以按根控制面、子面、有向角序首次遇到的顺序编号，再追加控制曲线，不能按坐标合并重合但不连接的点。0 级应特别约定：保持输入控制点编号，孤立点仍可追溯，包围盒另按引用情况计算。

原 QuadTriangle 中心三角面的创建没有像外侧三个子面那样设置 `SubdivisionLevel` 字段。观察到的这个内部字段不能直接当作数学细分级别；应另列旧核心诊断，实际输出级别以所请求的完整细分阶段为准。这是旧实现元数据差异，不应通过候选伪造字段来“修正”对照。

## ShipCAD 中没有采用的公式

固定参照提交为 `4d89e1498cbcea7b2c0c6b26aa7c8964b42279cd`。[ShipCAD 的平均公式](D:/桌面文件夹/项目/FreeShip_26/References/ShipCAD/ShipCADlib/subdivpoint.cpp:395) 使用 `sqrt(3/8 + cos(2π/n)/4)`，当前 Plus 在相应位置使用 `sqr(...)`。这不是语言精度差异，也不能因为 C++ 代码更方便就借来替换。平面、对称且中心恰好不移动的例子可能掩盖它，因此需要非平面中心峰值例题。

独立依据采用作者的 [Quad/Triangle Subdivision 论文](https://www.josstam.com/_files/ugd/cf1fd6_3c2078555e64467497d2d5ace85a4fec.pdf)，第 2 页 Figure 4 给出线性拆分后的平滑权重，第 3 页 §2.4 给出边界/折痕规则。它支持这里的小型数学例题，不是对整个候选实现的正确性证明。

可独立推得的例题：旧中心 z=1，周围旧点 z=0，拆边后的相邻中点 z=1/2。六价三角扇中心新 z 为 `5/8`；三价三角扇为 `7/16`；四价纯四边网格峰值按 Catmull–Clark 规则为 `9/16`。边界线使用 `[1/4,1/2,1/4]` 平滑掩码；角点应保持不动。它们应与 Pascal 对照分开记录，不能把候选公式复制到 Python 里后称为独立检查。

## 数值与观察探针

几何存储沿用 Single。当前机器前一轮已实测 FPC Win64 的 `Single/Double/Extended` 为 4/8/8 字节；本轮报告仍应记录实际编译器及类型信息，而非只继承这个结论。常量折叠、三角权重、面中心累加及最终平均都有中间舍入，不能只保证最后赋值是 float 就认为逐步等价。候选验证构建应禁用快速数学重排和融合乘加。

旧探针必须调用真实的加载与细分过程。当前观察方案在私有构建中为 `FreeGeometry.pas` 增加四个 Probe 只读属性，读取原始层名、曲线可见性、控制边后代标记、内部面级别；适配器另有一个 `ServiceStoredName` 只读属性。独立查看编译副本与原文件的 diff，仅见上述五个 getter 及局部 `ShowMessage` 抛错包装，没有算术改动。探针还恢复全部被适配器碰到的几何 include，并核对原文件哈希。隐藏环境中的完整性弹窗改为抛错，只改变错误呈现，不能改有效输入的算术。没有用新公式重写一套 Pascal 算法充当旧基准。

两个探针把有限 Single 数值提升后写 JSON；比较读回重构的 Single。这个结论不涵盖正负零符号位或 NaN 载荷，更不能称为内存逐位一致。独立实数期望可能与两边共同的 Single 舍入不同：应报告具体位置、实数期望、两边实测和误差，不得放宽旧新兼容标准使差异消失。

## 接口和验收边界

- 核心只依赖标准 C++ 数据结构，不依赖 Qt、窗口、文件 IO 或用户模型状态；Qt JSON 驱动仅在测试目标内。
- 不合法索引、缺边、重复边、非有限值、超限级别和明确不支持的混合曲线，应直接拒绝。拒绝分支不能被当作几何兼容通过。
- 点坐标变动应让所有已缓存级别失效；相同坐标和失败变动不应破坏既有结果。尚未实现局部增量传播，不因存在缓存而声称已经完成。
- 高级别生成失败不能发布半份缓存；同实例重复调用和新实例需检查确定性。未实际重复运行独立进程时，不把这些证据扩称为跨进程验证。
- 保留 Plus 来源、署名及 GPL 声明，记录 ShipCAD 只作比较的具体范围。这里的来源核查不作额外法律结论。
- 正式应用未切换到这个核心，桌面体验、完整切割、静水力、导出和编辑保存不属于本轮验收。

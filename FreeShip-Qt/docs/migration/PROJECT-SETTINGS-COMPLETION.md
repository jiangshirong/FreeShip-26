2026-11-09。逐项核对 `FreeProjectSettings.Edit` 与旧设置窗口后，将剩余有效行为接入 Qt；原来没有实际作用的控件不照搬。

| 原设置 | Qt 处理 |
| --- | --- |
| 名称、设计者、说明、文件创建者 | 常规页编辑；遵循文件编码，保存、撤销和取消使用同一事务。此次补齐创建者。 |
| 单位、主尺度、中船分界、精度、交线简化 | 已有原生编辑；单位换算同时处理相关几何及工程数据。 |

| 水下颜色、不透明度、预览、附加表 | 已接入显示、保存与计算窗口。 |
| 自动移到基线 | 改为主尺度页的一次性操作“确认时将船底移至基线”。计算报告时不改船模。 |
| 水温 | 放在实际消耗黏度的推进初步设计、操纵性计算窗口，提供“按水温换算黏度”。 |

## 船底对齐

使用当前静水力图层控制网的船底基准，将全部控制点一起平移，包括隐藏图层；没有静水力面时沿用现有船底定义。标记、四类剖面和流线起点跟随平移，失效的交线与流线缓存清空。背景图沿用其既有图片坐标，主尺度、吃水和计算参数不自动改写。

有锁定点、锚点或直线约束时，整笔请求拒绝，不再跳过个别点而留下变形船体。同一次修改单位时先换算，再在目标单位中对齐。与工程信息一起确认只产生一次撤销；船底已在零位时不会增加空历史。

旧 `EnableModelAutoMove` 字节保持兼容，Qt 不以它触发报告副作用。原版本仍可能读取并执行该旧开关；新操作没有给旧格式增加新字段。

## 水温与黏度

沿用原 `FindWaterViscosity` 的 0–30°C 表及线性插值，不扩展为新的水体物性模型。修复 30°C 端点返回零的问题，界面不允许表外外推；实际水体的运动黏度仍可直接填写。

操纵性计算原有黏度字段可以存入 FBM；提取船体尺寸现在保留已填写或已存储的黏度。推进初步设计原先隐藏的 15°C 常量改为可编辑黏度，默认值保持 1.189 × 10⁻⁶ m²/s，传给原求解器的单位仍为 m²/s。

FBM 没有保存水温及该推进方法黏度的位置，因此不挪用保留字节。窗口明确提示使用现有“保存参数 / 载入参数”保存完整工况；报告也记录实际输入。默认工况的求解器输入与原版保持一致。

## 验证与边界

`run_tests.py --suite qt-project-completion` 纳入统一测试。覆盖 45 个格式版本、逐字节创建者编辑、整船平移的独立坐标与平面预期、锁定拒绝、单位混合修改、只读静水力、撤销/重做/保存重开、原求解器黏度输入及真实 Qt 菜单回调。温度表端点、插值和域外拒绝并入现有窗口测试。

旧工程设置和计算回归继续保留，测试源码位于 `FreeShip-Tests`。最终结果以安装回执及其引用报告为准；隐藏 Qt 事件、截图与参数往返不代替真实桌面操作验收，也不代表重新认证旧经验表及外部求解器。

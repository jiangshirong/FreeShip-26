# 专业计算图表

2026-11-09。覆盖十个阻力、五个推进、风载及加速/制动，共 17 类曲线窗口。
操纵性以文字报告为主，附加质量使用矩阵和型值预览，两者不增加虚构的曲线。

## 显示

默认显示全部曲线。图例保留原 LFM 中声明的颜色、线宽和线型，可以逐条隐藏或恢复；
“仅显示选中曲线”保留单曲线查看方式。常规页与结果页共用显示状态，数据表始终保留
完整数据。Passport 同名曲线在图例后加序号区分，没有把序号冒充转速或进速系数。

阻力和功率使用各自的纵轴；系数与效率沿用明确标注的无量纲组合。
同一横轴下超过两种量纲时分成上下对齐的图；窄窗口也会分开显示，避免多个纵轴挤在一起。
加速历程中的距离、航速、转速、推力和转矩各有对应单位。刻度按数据范围与字号取整，
支持负值和常量范围，重复横坐标按原顺序绘制，缺失值断线而不跨越连接。

颜色与线型由 `maintenance/generate_calculation_charts.py` 从原始窗口提取，
来源指纹在 `src/app/calculation_charts-origin.json`。继续使用 StudioLight，未修改语言目录。

## 精度与一次标注修正

绘图模型保留每个 double 坐标及原顺序，两个窗口共用一份坐标数据。
显示开关只影响画面，不改变计算结果、数据表或导出。曲线使用完整折线绘制，未抽点。

推进 Task1 的 `Series3` 取自 `RES1` 第 1 列，实际为螺旋桨直径，原共用纵轴标题却把它
标为主机功率。现在单独标成“螺旋桨直径 (m)”，数据表、JSON 和 CSV 使用同一正确单位。
原数值和求解器协议保持不变；读取旧结果的图表也识别该曲线。旧对照测试保留全部数值
比较，仅对这一个错误标题允许修正，并另断言正确单位。

## 绘制成本

2026-11-09 追加优化。保留的加速样本有 1,116,635 个点。同一独立图表在优化前首次
绘制为 1478 ms，其中范围扫描 3 ms、坐标映射 7 ms、CPU 描边 1464 ms，瓶颈是
带抗锯齿的粗折线绘制。仅缓存最后一张画面不能解决第一次显示及切换组合的问题。

大曲线改用 Qt 自身的 OpenGL 绘图库，仍传入每一个原始点，继续使用 QPen 的线宽、
线型、连接和裁剪规则。要求至少 4 重抗锯齿；当前显卡提供 8 重。没有抽点、平滑或
改写计算坐标。数字、网格和小曲线仍走原软件绘制，不改数据表或任何导出函数。
不同绘图后端的边缘抗锯齿覆盖可能略有差别，不能宣称截图逐像素完全一样。

每条曲线的有限点范围与连续段数在读入时求一次。曲线图层分别缓存，键包含范围、
绘图区、线宽和设备像素比例；选中一条曲线时只重建受影响的图层，恢复已有组合直接
合成。每个图表的图层缓存上限为 64 MiB；替换结果会清空旧图层。尺寸或刻度变化时
重新绘制，避免用旧位图拉伸导致模糊、漏图或范围错误。

显卡上下文及着色器在进入加速窗口时提前准备，耗时部分在专用线程执行。离屏表面
仍按 Qt 要求在主线程创建、销毁；绘制任务串行使用同一个上下文，图像返回后才合成。
先由工作线程建立上下文并加载驱动，再用实际格式创建表面，避免主线程先加载驱动。
本机复测主线程准备约 5 ms；后台准备与事件排队的时间仍存在，与填写参数及后台
计算重叠，不再放在结果首次绘制中。没有嵌套 GUI 消息循环等待初始化。
参见 [QOffscreenSurface 线程约束](https://doc.qt.io/qt-6/qoffscreensurface.html)
及 [QOpenGLContext 线程归属](https://doc.qt.io/qt-6/qopenglcontext.html)。

最终版本同机独立图表冷启动首次绘制约 130 ms，包含尚未完成的显卡准备等待。
正式计算窗口提前准备资源后，常规/结果图首次绘制约 45–75 ms，新显示组合约
13–95 ms，恢复已有组合约 1–4 ms。读取完整曲线约 85–105 ms，单独记录；
这些是本机样本测量，不是求解器总耗时或所有显卡的性能保证。完整坐标哈希仅在测试
取证时惰性计算，普通显示不再为这项诊断额外消耗约 0.09 s。

最终安装目录复测：两处图表首次绘制 73.2/57.7 ms，新组合 46.3–94.8 ms，恢复组合
1.7/3.2 ms，主线程显卡准备 3.3 ms，数据读取 83.5 ms。保留波动，不只挑最快一次。

显卡不可用或抗锯齿能力不足时保留软件绘制；可用 `FREESHIP_CHART_SOFTWARE=1` 强制
该路径排查。软件路径保持全量数据，不能承诺它也达到上述 GPU 时间。

## 验证与边界

`run_tests.py --suite qt-calculation-charts --runtime <运行包>`：

- 用已保留的 17 类完整结果回放正式绘图组件，逐位核对每个坐标。
- 从实际菜单执行计算，检查两处图表、图例开关、单曲线切换、缓存、数据表及代表格式导出。
- 独立样本覆盖负数、常数、重复横坐标、缺失值断线、三种字号与宽窄窗口。
- `qt-calculation-chart-speed` 专测百万点及多个设备缩放倍率；实线、虚线、点线、
  点划线对照全量软件绘制，双向检查实色像素覆盖偏差不超过一个物理像素。
  额外检查单点尖峰、断点、竖直段、回头段、恢复图层截图及替换结果后的缓存失效。
- 另检查后台显卡准备尚未完成时直接关闭进程，避免退出时等待 GUI 回调造成死锁。
  排查中还捕获了 Intel 驱动在跨线程销毁未使用上下文时的崩溃；现在上下文的创建、使用、
  销毁均在同一工作线程，并在 `aboutToQuit` 中完成清理。测试断言产品退出钩子已执行。
- 实际窗口记录第一次绘制、切换组合、缓存复用的分段时间；数据准备与显卡准备分别记录。
- `maintenance/profile_calculation_chart.py` 保存逐阶段诊断及绘图库对比入口。用于同机
  性能调查，不单独充当精度验收；早期 fast1 采样在构建完成前启动，不能用作优化后数据。
- `maintenance/debug_calculation_chart_shutdown.ps1` 保留 GDB 退出崩溃诊断命令；调试器会影响
  调度，且依赖本地工具链，不充当自动回归。正式退出检查已纳入性能套件。
- 加速样本只保留小型观察报告和截图，不再复制 120 MiB 的 JSON 和 73 MiB 的 CSV。
- 另跑推进原协议对照与 19 个计算窗口的布局回归，安装后从实际 dist 路径再验证。

隐藏 Qt 事件和截图不代替真实桌面验收。CALCPROP 三个真实任务仍因旧程序不产出结果而
受阻，协议样本只证明绘图与数据流；DBFview 缺失也未解决。没有把这些问题记成通过。

历史数值基准由测试文件的 `REFERENCE` 指向，并在报告中记录指纹；它们属于仍被引用的
基准，不应按普通历史输出删除。也可以通过直接运行测试脚本的 `--reference` 指定副本。

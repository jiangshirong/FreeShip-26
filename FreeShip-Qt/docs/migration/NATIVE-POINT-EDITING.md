# C++ 控制点移动与 FBM 坐标写入

`move_point` 和 `move_points` 现在由 `src/document/point_edit.cpp` 执行。
Qt 的拖动提交、坐标输入和批量坐标修改沿用原入口，没有改变 StudioLight 界面。
运算适配器在外部文档模式下拒绝这两个旧编辑命令，防止新服务又退回 Pascal 代算。

单点移动保留锚点相对位移、硬锚点直接移动限制、直线约束投影，以及依赖点的联动。
坐标和中间运算沿用原 Single 精度和顺序；不启用 fast-math 或融合乘加。
长依赖链使用显式栈，避免递归耗尽调用栈；异常复杂的联动超过两百万次访问时取消。
批量移动先验证全部 ID、坐标、锁定和约束关系，再生成候选，不允许只成功一部分。

`Fbm::withPointPositions` 根据原二进制中的点位置写入新坐标，保留无关字段、记录
填充、名称、计算设置和图片。剖面线的定义保留，旧剖切结果删除并标记未构建；
流线起点、视图和选择状态保留，旧流线缓存同样失效。无变化操作保持原始字节和重做栈。
未知扩展仍禁止编辑，避免尚未理解的派生字段失效。

候选中的已计算坐标增量交给原适配器，直接更新现有运算副本，再重建尚未迁移的
四视图网格和分析数据；不再重复传播约束或每次重新载入整份 FBM。原生型线图继续生成
场景与 DXF。服务校验返回坐标、身份和输出后才提交历史；失败则保留原文档。
适配器恢复候选时直接使用传入的 FBM 和 ID 映射，不再重复调用 SaveProject 编码。
保存使用 C++ 候选字节；撤销、重做、另存与再次打开继续走统一文档状态。

这次迁移的是绝对坐标编辑及其联动和持久化。平移/缩放/旋转菜单的整体模型语义
还涉及尺度、剖切平面和标记；拓扑、约束定义编辑、任意属性编码、四视图网格及
专业计算仍有 Pascal 依赖。不能把局部字段写入称为完整 FBM 原生重新编码。

测试代码保留在 `FreeShip-Tests/qt_point_edit.py` 和 `qt/fbm_codec_tests.cpp`，已纳入
统一 `qt-document` 套件。覆盖 0–44 格式分支的坐标写入、无关块逐字节保留、缓存
失效、非法批量修改、锚点链、斜线投影、锁定依赖、撤销重做和旧读取器回读。
对照包括完整模型、场景、DXF 和剖面侧数据，不采用浮点容差掩盖差异。
测试报告记录纯点编辑耗时与整个请求耗时，不能把前者当成完整界面响应时间。

最终安装清单、回归和耗时见 `FreeShip-Tests/maintenance/point-installed-20261102.json`。
真实桌面交互和全部视觉保真仍单列验收。

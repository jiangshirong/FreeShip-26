# Qt 界面语言

2026-11-10。此前把“译文交给翻译模型”理解成不接语言入口，是遗漏。
语言选择、切换、保存和资源装载属于程序工作；补译及专业术语审校仍交给用户指定的翻译模型。

## 使用

顶栏「菜单 → 首选项 → 常规」选择界面语言，确定后保存，取消不生效。
下次启动先读取语言，再构造窗口。语言不属于船模，切换不发送几何重算请求，
不增加文档修订号或撤销项，也不改工程名称、设计者、文件编码及计算数据。

勾选双语言切换并选择两个不同语种后，可以用 `Ctrl+Alt+L` 或菜单中的语言切换项来回切换。
快捷键只属于当前 Qt 窗口，不注册系统全局热键；模态设置窗口打开期间不执行切换。
常用菜单与已绑定静态标题即时更新，重新打开的窗口使用新语言。
已生成报告、表格和数据相关文字不做反向替换；需要新语言时重新打开相应窗口。

## 回退与可靠性

顺序为 **所选语言 → 已有英文 → 中文源文**。选择中文时直接使用中文源文。
上游 PO 的英文是核对旧功能原意的主要依据，但不能据此声称所有英文专业术语都已验证。
Qt 新写的中文提示没有现成英文时，保留中文，不用自动生成的译文填空。

英语包缺失或目标包损坏时，启动仍可完成：优先用有效英语包，否则用内置中文，
并在状态栏说明问题。自动回退不覆盖用户保存的选择。
设置窗口应用无法装载的语种会拒绝保存，保留当前语言和其他设置。
读取包时限制文件大小、语言标识、版本、条目类型，并校验 `%1`、`%L1`、`%n` 参数集合。

## 资源与翻译交接

- `src/app/languages/*.json`：运行包使用的 Qt 字串映射，随安装包放在 `languages`。
- `tools/prepare_ui_language.py --catalog`：从已有 PO 复用无歧义条目；不做机器翻译。
  少量常用按钮按明确英文源条目对应，资源标识符如 `DeleteSelected` 不当作英文译文。
- `UI-LANGUAGE-SOURCES.json`：上游 PO 指纹、逐条来源、各语种缺词清单。
- `UI-LANGUAGE-STRINGS.json`：中文源文及代码位置，供翻译模型定位。

本轮提取 901 条 Qt 字串，英语复用 125 条，其他已有语种按资源实际内容载入。
这只是现成条目的接线数量，不是整个软件的翻译完成率，更不是专业术语准确率。
不能把语种出现在选择框里当作该语种已经完整翻译。
PO 及派生内容沿用项目原有许可证与来源声明；没有修改 Lazarus 基线资源。

旧 INI/DTA 的语言字段仍不自动导入：旧语言文件名与 Qt 语种 ID 不是同一接口。
导入其他偏好后，语言在本窗口明确选择。旧语言资源目录也不作为 Qt 文件搜索目录。

## 验证边界

按用户要求，窗口验收以英语为唯一目标语种。其他包只检查能否装载、条目格式和占位符；
不靠抽查另外一两个语种来声称覆盖多语言。中文仅用于检验原文和双语言往返。

`FreeShip-Tests/run_tests.py --suite qt-ui-language` 接入独立语言包样本及实际 Qt 首选项回调。
覆盖回退顺序、占位符、坏文件、重复切换、静态文字更新、用户输入保护，以及保存、取消、
重启、双语言切换、无效组合、模型修订与导出不变。测试源码保留在统一测试工程。
`qt-preferences-ui` 继续核对原有设置、导入、保存事务和失败回退；`qt-dialog-layout` 观察字号和缩放。

这些是隐藏窗口回调和截图证据。实体快捷键、桌面焦点、多屏及用户对原设计的观感，仍要单列验收。

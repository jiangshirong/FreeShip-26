# 控制曲线和流线

2026-11-01。这一批补四视图里的曲线定义、流线起点、选择、删除和文件往返。
编辑状态仍由一个 Pascal 文档持有，Qt 负责命令入口、交互和绘图。
流线沿船体的追踪算法尚未改写为 C++，也没有引入另一套流体计算。

## 现在可以做什么

- 在“边”菜单选择控制边，再由所选边生成控制曲线。相连边组成一条曲线，
  不相连的边分别生成；闭合链保留首尾重复点，分叉点处自动分链。已有曲线的边不会重复创建。
- 选择控制曲线或流线后，可以删除、撤销、重做。删除曲线定义保留船体控制网。
  改动相关控制点、删除控制边或调整模型精度后，曲线随同一文档版本更新。
- 从“可见性 → 流线 → 添加流线”进入取点，在任一正交视图的水下船体上点击。
  起点来自视图坐标，与背景图及其比例无关。Esc 或右键取消，不产生撤销记录。
  取点时切到线框显示；已有流线在填色模式下隐藏，沿用旧版规则。
- 显示开关、控制曲线定义和流线起点写入 FBM，保存重开后继续使用。
  旧格式需要时自动提升到可以存储相应数据的版本，防止撤销和保存时丢失定义。

控制曲线 ID 和流线 ID 分属各自类型。撤销恢复原 ID，新对象不占用已删除对象的 ID。
非法编号、重复编号、过期请求或输出失败会回滚，不保留半完成的编辑。

## 绘图和计算

正交视图把已有 Single 样条系数转成三次 Bézier 段，直接交给 Qt 绘制。
透视图按投影后的控制多边形误差细分。横剖面跨船中位置的曲线先求交再分段，
前后体分别映射，避免穿过中心的假连线。点选复用同一投影路径，命中区域按需生成。

三个正交视图和透视图共享不可变曲线数据。普通重绘复用投影路径；镜头变化只更新
投影，不重新细分船体或追踪流线。这些显示路径不参与型线图场景和 DXF 的生成。
FBM 中仍保存原控制网、曲线定义和流线数据，不把屏幕采样结果写回模型。

回归还发现并修复了流线缓存失效遗漏：原 `FreeShip.inc::FSetBuilt` 在船体已经
被点或精度设置标为未构建时会提前返回，绕过后面的流线失效循环。Qt 服务在
`TDocument.InvalidateAnalysis` 中明确清除流线缓存，避免改点或改精度后仍显示旧线。
这项修复只在迁移服务中生效，旁边的旧版工程保持不动。

代码依据是当前 Plus 的 `FreeEdit.inc::Curve_Add/Flowline_Add`、
`FreeSubdivisionSurface.inc::Rebuild`、`FreeSubdivisionControlCurve.inc` 和
`FreeFlowline.inc`。表面重建使用 `RebuildSpline`；另一个名为 `Rebuild` 的方法
对端点折角的处理不同，不能随便互换。测试探针直接观察前者生成的结果。
这里没有借用 ShipCAD 的窗口或流线实现。

## 验证与范围

统一测试入口为 `qt-auxiliary`。源码保留在 `FreeShip-Tests/qt_auxiliary.py`、
`qt/auxiliary_tests.cpp`、`QtEditingFixture.pas` 和 `qt_editing_fixture.py`；
真实应用动作的隐藏工作流在 `src/app/auxiliary_workflow.cpp`。

回归覆盖闭合链、不相连链、已有边重复提交、分叉分链、依赖边删除、稳定编号、
发布失败回滚、旧格式升级、改点、单位转换、精度切换及保存重开。独立旧核心探针
逐点比较曲线和流线，并核对型线图与 DXF；视图测试另有三次曲线解析预期、
三处跨面分割、投影误差、点选、取点及取消操作。

2026-11-02 已补齐分叉分链和选中控制曲线的曲率梳。控制曲线可通过改点、拆边、
折叠调整；此前笼统写的“整形/拟合工具”没有对应的独立旧命令，详见[范围核对](MODEL-EDITING-COMPLETION.md)。
流线落点无有效线段（只有停滞点或没有命中）会提示并保留模型。连续添加流线的
旧快捷手势仍需与桌面交互核对。流线仍是旧版几何追踪结果，不能当作 CFD 计算结论。

隐藏 Qt 动作与离屏图片不代替桌面操作验收：实际鼠标和焦点仍为 `not_run`，
完整视觉一致性为 `review`。最终运行报告与交付记录见下方。

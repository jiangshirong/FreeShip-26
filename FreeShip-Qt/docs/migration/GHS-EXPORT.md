# GHS 船体几何输出

文件菜单的导出列表已接入 GHS（`.gf`）。断面生成、单位换算和写文件都在 C++
完成。读取 FBM、维护文档和编辑历史仍使用现有桥接核心。

## 输出范围

- 使用工程里已定义的横剖站，以及全部参与静水力的图层；不受图层显隐、镜头、
  四视图半船开关或型线图简化选项影响。不自动增加首尾站或中间站。
- 本入口输出一个对称排水体 `HULL` / `HULL.C`，支持原侧在正 Y 或负 Y 的半船。
  非对称、跨中心线的完整控制网、并列船体和舱室部件划分仍未接入。
- 保留模型原点；纵向为 `-X`，横向为半宽，垂向为原 `Z`。可选米或英尺，
  英制工程的水密度换回相对密度后写入。外板厚度不另外增加。
- 敞开甲板只有勾选“将敞开甲板按水平线封到中心线”才封顶。不补船底或横向缺口。
  上下分离、均收在中心线且高度范围不重叠的轮廓，用中心线连接；连接段的面积、
  一阶和二阶矩均为零。球鼻艏附近可能出现这种截面。
- 保留原始型值点和折角，按三次样条的控制多边形界限递归离散，弦误差为 0.1 mm。
  这个数值仅描述样条到折线的离散误差，不是原曲面精度、纵向站距误差或整体
  排水量误差。细分档位、原始单精度求交及其容差仍继承当前原生几何核心。
- 文件说明字段沿用 ASCII；中文路径和空格原样保留，项目名非 ASCII 字符用 `?`。

至少要有两个有效横剖站。没有交到船体的站位在导出结果中计数；重复站位、
自交、重叠轮廓或超过计算预算会停止，不删点凑出一个文件。

## 与旧版的差别

原 `Units/FreeEdit.inc::File_ExportGHS`（2210–2382）先写 `NParams`，随后遇到
折角又插入点，声明数量可能小于后续记录数量；参数列表本身也会重复折角参数。
新实现先生成完整点列，再写实际点数，不再把复杂断面压成固定 100 个采样点。

`Units/FreeShip.inc::FBuildValidFrameTable` 会尝试强行拼接分段，并将所有断面
下移到最小 Z 为零。新入口保留原点；只拼完全相同的端点，不使用显示交线的
近邻拼接和短片段过滤。甲板封顶也从隐式操作改为明确选项。

原导出还会删除文件名中的空格。新程序按所选路径原样提交，用临时文件完成后
原子替换；生成失败、取消或模型版本变化均不替换已有文件。

`src/core/hull_sections.cpp` 负责共用断面，`src/core/ghs_export.cpp` 负责 GF 文本，`src/native/export_worker.cpp`
运行独立进程。Qt 对话框持有导出时的文档身份和版本，核对返回文件哈希后才提交。
计算超过 90 秒或关闭窗口会终止本次导出进程；主程序退出时子进程也退出。
这条路径不会重写 FBM、修改控制网或触发旧版绘图。

## 验证及边界

统一测试入口为 `qt-ghs`。独立 Python 读取器检查记录数、结束标记、单位、
断面顺序和逆时针面积。箱体另验面积、重心和全船体积；上下两段的合成例验证
中心线连接没有增加面积或改变重心。自然三次曲线用解析多项式检查离散误差。

三个现有模型经过隐藏 Windows Qt 的实际导出入口。没有横剖站的两个小模型应
明确拒绝；9a 保留 11 个站和 2,171 个点，其中最前站有两个上下分离轮廓。
另验修改控制点后更新、撤销还原、重复生成、导出取消、旧文件保护及原场景/DXF
保持不变。界面截图已查看；真实鼠标、系统文件选择器和完整 UI 一致性未验收。

GF 记录骨架对照现有 Plus 输出。几何含义同时参考厂商的
[训练手册](https://ghsport.com/support/TrainingBook.pdf) 和
[部件说明](https://www.ghsport.com/support/tutor/pmtut/pmgeo.htm)：中心线部件可由
半船定义，点沿逆时针排列，顶部闭合。厂商也记录过
[多分离轮廓的处理](https://ghsport.com/support/%21CHA1450.HTM)。
中心线连接的数值等价由本地独立面积与矩检查确认，不等于已通过接收软件验收。

目前没有 GHS 商业程序，也没有当前版本的完整 Appendix A。
[厂商格式页](https://www.ghsport.com/support/APPEND-A.HTM) 要求查看随软件的手册。
因此报告把商业 GHS 读取，尤其分段中心线轮廓的接收结果，保留为 `not_run`，
不能把自有解析器通过称为 GHS 认证或审批可用。

Archimedes 与 PAM 已接入，见 [船舶格式](SHIP-FORMATS.md)。Michlet/AddMass、
部件交换及其余导入仍继续单列迁移。

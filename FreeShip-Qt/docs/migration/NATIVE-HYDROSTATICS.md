# 静水力与稳性计算内核

2026-11-03。保留现有 Qt 窗口和 StudioLight 外观，替换背后的计算路径。

`src/document/hydrostatics.cpp` 直接读取当前 C++ 文档，处理设计吃水计算、
吃水表、固定/自由纵倾平衡、KN、GZ 及 GZ 积分。默认参数也从 FBM 记录读取。
正式服务的 `hydrostatics`、`hydro_defaults` 不再调用 Pascal；旧入口遇到
外部文档请求会明确拒绝，避免悄悄回落。旧分支只用于对照及尚未迁移的内部调用。

## 这次去掉的重复工作

旧 `FreeHydrostaticCalc.inc::CalculateVolume` 在每次体积积分后调用
`CalculateMidshipLocation`。稳性二分求解只用排水量和浮心，不读取最大截面位置，
却会反复做 128 个初始截面及后续峰值细化搜索。

新实现把体积积分、完整静水力报告和平衡求解分开。稳性迭代不生成截线，也不求
最大截面；完整报告仍保留这些计算。一个文档状态只构建一份细分网格和求交索引，
同一批工况、下次点击计算及默认设计排水量共用。改点、图层、单位、计算设置或
撤销后按文档状态失效。这是进程内缓存，没有给 FBM 添加新字段。

## 数值边界

体积、浮心、湿表面积、面积与惯性矩、材料重量来自当前 Plus 的
`FreeHydrostaticCalc.inc`、`FreeIntersection.inc` 和 `FreeSubdivisionLayer.inc`。
沿用 Single 存储、面遍历顺序、样条取值和 500 段积分；没有降低采样精度。
曲线简化采用型线图已经核对过的实际调用规则，避免在旧版不简化的位置额外删点。
原作者署名和 GPL-2.0-or-later 说明保留在源码中；此模块没有采用 ShipCAD 算法。

平衡求解沿用已在 Qt 流程中验证的有界二分法。排水量残差限为
`max(目标排水量 × 2e-6, 1e-6)`，纵向平衡残差限为
`max(船长 × 2e-6, 1e-6)`。不会采用旧 `Balance` 的吃水减 0.01 等处理。
参与计算的边单独统计相邻面；不把所有 Y=0 边都当成封闭对称缝。
超出完整浮力范围、漏点、非流形边和不收敛工况明确报错。

2026-11-09 已补齐[非对称船体截面与水线面计算](ASYMMETRIC-HYDROSTATICS.md)。
实际参与的非对称层改用有向三角船面截线积分，水线面、漂心、惯性矩、稳心及截面积
不再留空，Bonjean/SAC 同时接入。扭曲四边形的体积裁切也统一到固定三角船面。
全对称路径继续保留既有对照算法；后续已补齐[非对称侧投影与标注](LATERAL-PROJECTION.md)，
旧单侧进流角仍未提供。
经验天气衡准、规范评定和破舱稳性不属于本次迁移。

## 验证

`FreeShip-Tests/qt_native_hydrostatics.py` 接入 `qt-document`，复用原有解析测试，
并将方箱、曲面船型、课程船型和双材料模型逐字段与旧核心对照。没有放宽原来的
`3e-5` 数值容差。方箱的体积、浮心、GZ、自由纵倾另有独立公式预期。
覆盖英制换算、横向重心偏置、进水、取消、错误输入、文件发布失败、撤销、
缓存失效与设置保存。故障注入停止测试自己的旧适配进程后，再计算同一报告，
确认新内核确实不依赖旧进程。

现有 Qt 静水力入口还会执行单工况、吃水表、稳性、保存参数、取消和再次计算，
核对 JSON、全精度 CSV、TXT 与 PDF。型线图场景和 DXF 沿用原来的精确比较。
这是隐藏窗口中的生产回调验证，实际桌面交互和视觉一致性仍单列。

构建和报告放在 `C:/FreeShip26Tests`，测试源保留在 `FreeShip-Tests`。
交付来源与具体结果见 `FreeShip-Tests/maintenance/hydro-native-installed-20261103.json`。

剩余的旧分析端依赖包括阻力/推进计算器及其船体参数提取、板材展开、IGES 准备，
以及快照水静力标注和型线图历史中剖位置等内部调用。此次完成的是 Qt 静水力与
稳性计算方向，尚未彻底移除旧分析端。

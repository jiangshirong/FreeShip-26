# 原生平面与样条验证

2026-11-01。ShipCAD 的第一批可复用计算已提取为 `src/native`，不依赖 Qt 控件、
绘图、文件格式或全局模型。它提供平面构造、投影、镜像、盒相交、直线求交，以及
样条参数化、求值、导数和采样求交。正式应用仍由原 Pascal 服务计算。

## 为什么先做这一小块

这些运算会被后续细分曲面和交线使用。先让同一组输入分别通过原 Pascal 函数和
C++ 实现，能在最小范围内查清差异。两套代码都算错的可能性，则由可手算的平面、
直线和自然三次样条例题补充检查。仅凭移植代码能编译、画出来像船，不能接管计算。

ShipCAD 和当前 Plus 已有几处实质差异：弦长参数化、折角处理、样条插值中间量、
交点去重规则都不能照搬。这批按当前 Plus 对齐，保留旧一阶有限差分和采样求交方法。
三点共线、负侧平行线误判共面、复用求交数组残留等问题，也在独立用例中处理。

直线求交另修了极小点积下溢和大小项抵消导致的误判。这个新接口使用 double 中间值
和短补偿求和；先用未舍入的参数计算交点，再转换成 float 输出，不可表示的输出明确
拒绝。这项有独立解析反例，不改变需要与 Plus 对齐的样条、投影和镜像运算。

实测还查出了语言转换时的舍入差异。当前 FPC Win64 的 `Extended` 是 8 字节，
所以 C++ 求值参数用 `double`。样条重建中的一些常量必须采用 `float`，而一阶
有限差分的 `t±1e-3` 又要先用 `double` 再回到 `float`。这些边界结合原程序运行
和编译指令核对；没有靠放宽容差消掉差异。完整来源说明见
[PROVENANCE.md](../../src/native/PROVENANCE.md)。

## 缓存和错误输入

点或折角变化后只标记样条系数失效，下一次查询重建一次。重复查询、设置相同值
不会重算；改变采样段数也不重算样条系数。重建先生成临时数组，成功后再发布。
这是单条样条的缓存，不是整个船体的局部细分更新，也没有增加磁盘缓存。

无效平面、非有限坐标、越界索引和不可表示的计算结果有明确处理。两点及以上的
样条求交必须给正采样段数，零段数会拒绝。Plus 的零段数实现只检查起点，可能返回
看似完整的交点列表；新接口不沿用这个行为。空/单点的安全数组和退化平面的处理
也单独记录，不能算作与旧版数值完全等价。

## 怎么复现

在工作区运行：

```powershell
python FreeShip-Tests/run_tests.py --suite qt-native-geometry --output FreeShip-Tests/reports/native-geometry-new
```

它会在新目录构建候选与 Pascal 对照程序，再运行固定输入、独立例题和三模型的
样条抽样。结果分为 `pass/fail/review/not_run/error`，构建清单记录计算代码、
测试入口、工具和输入文件的指纹。`build-native.ps1` 只构建这一独立目标，不打包应用。

真实模型输入直接取自旧核心的样条点、折角标记和采样段数。盒体和合成船体没有
保存剖面，测试在私有模型实例上用旧核心生成中间切面；9a 使用抽取的已存剖面，
另补一个中间斜切面。采样范围和来源逐项写入 `model-oracle/models.json`，未覆盖的
剖面不冒充已经测试。导出的输入还要重新交给原 Pascal 样条，检查序列化是否丢失信息。

比较使用 JSON 中有限数值重构后的 Single 表示，不设经验误差阈值。正零和负零合并
比较，因此这里不声称完整 IEEE 位模式相同。直线与平面求交没有对应的旧公共函数，
使用独立数学预期，不能列为旧程序交叉验证。

新增节点两侧采样时，还查到一项原版已有的舍入限制。三点 `(0,0,0)`、`(1,1,0)`、
`(2,0,0)` 的自然样条，在 `t=0.9999999403953552` 处，二阶导数的 y 分量数学值为
`-1.430511474609375e-6`，原版和候选都得到 `-1.9073486328125e-6`。误差来自
Single 插值乘法的舍入，在端点附近相减后显现。这项保留为 `review`，没有扩大容差，
也没有为追求数学值而改变现有计算结果。独立精确例题仍检查原来的九个可精确表示
采样点；新增采样全部保留在旧核心严格对照中。后续精度改进需要单独设计误差界与回归。

## 后续接入

剖切。显示网格不能代替原始控制网。等这些模块完成，才能在正式应用中逐项替换

型线图打开时间、拖动帧率得到新的提升。当前交付程序、旧版和已验收试点保持原样。

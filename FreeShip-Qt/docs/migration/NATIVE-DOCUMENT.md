# C++ 文档状态与 FBM 保存

Qt 现在启动 `FreeShipDocumentService.exe`。它是活动文档的唯一提交者，持有
文档身份、递增版本、完整 FBM 状态、对象 ID、撤销/重做和保存点。原 Pascal
服务保留一个运算工作副本，用来执行尚未迁移的建模与专业计算算法。

这次接管的是整个打开、编辑、撤销、保存、重开流程，不限于一个窗口。工程属性、
点和拓扑、分组、约束、标记等现有编辑都经过同一个 C++ 事务入口。界面继续使用
原来的 StudioLight 和不可变快照，没有增加第二份可以独立修改的活动模型。

## 哪些已经原生，哪些还依赖 Pascal

`src/document/fbm_codec.*` 用 C++ 遍历 FBM 二进制结构，检查长度、版本、索引和
数量上限，识别控制网、图层、交线、背景图、计算设置、约束、锚点和分组。
文件版本是磁盘中的枚举序号 0–44，不是程序显示的 5.3.3。

未修改的文件使用原始字节原样保存，包含缓存、填充字节、预览图和不认识的尾部。
保存用 `QSaveFile`，不启用直接覆盖退路。解析后的状态不可变。

**单点和批量坐标编辑及其坐标写入已迁入 C++，见[控制点编辑](NATIVE-POINT-EDITING.md)。**
其余 FBM 字段编码、几何编辑算法、四视图网格及专业计算仍有 Pascal 依赖。
其余编辑由适配器返回完整二进制工作快照，再经 C++ 验证和提交；不是把所有算法都
迁完，也不能把这次的原样写出称为任意字段的完整 C++ 重新编码器。

Pascal 的 `DocumentAdapter.inc` 只负责交接运算状态及稳定对象 ID。它保留一个
工作状态用于操作失败回滚，不再为正式 Qt 会话持有长期撤销栈。原有独立 Pascal
测试仍可使用原接口，作为对照。旧版安装和源码不变。

## 提交与恢复

- 每个操作检查文档 ID 和预期版本。过期请求不会修改文档。
- 修改先在适配器完成；C++ 校验 FBM、ID 绑定、模型、场景及型线图文件哈希后，
  才加入历史。失败不改变当前状态；下次操作从已提交状态恢复运算副本。
- 撤销/重做恢复完整状态并递增版本。保存点跟随状态身份；撤销回保存点即清除
  修改标记，另起编辑分支会清掉旧的重做分支。无变化操作不产生历史。
- 对象 ID 的分配上限独立于当前历史位置，撤销后新增对象不会复用已发出的 ID。
- 历史沿用原内存预算，至少保留两个状态。保存成功并经界面确认目标原子替换后，
  才标记为已保存；生成私有保存副本本身不清除修改标记。
- 运算适配器退出时，C++ 中的工程和历史仍在，保存无需启动 Pascal。下一次
  计算操作重建工作副本。关闭 Qt 会终止本次拥有的子进程及其后代。

原 Pascal 保存会按对象地址整理点序，所以必须同时保留其序列化次序对应的
稳定 ID。未修改的原始文件另行保留，不能把原文件的点序直接配上整理后的 ID。
这是本次状态分层的原因，不是第二个模型所有者。

## 格式边界

输入和快照限制为 512 MiB，集合条目有独立上限。JPEG 仅检查封装，不在核心
解析器里解码；几何是否适合具体计算仍由对应算法检查。

现有 80 个样本覆盖 18 个历史版本序号，范围为 16–43。0–44 的其余格式分支
有合成数据检查，不能视为全部历史程序实物文件都已验证。
早期 Plus 计算参数布局共用版本号，部分短布局与截断文件无法仅靠版本区分，
检查报告会列明历史布局和警告。未识别尾部在原样保存时完整保留；当前禁止对
这类文档编辑，以免旧运算适配器丢掉扩展。历史布局歧义仍不能一概消除。

进程内恢复已覆盖；整个 Qt 程序崩溃后的自动恢复文件、跨重启撤销历史及持久
计算缓存没有在本轮实现。接管状态所有权为后续工作提供了入口，不代表已完成。

## 验证

统一套件 `qt-document` 包含：

- 80 个真实 FBM，历史版本合成例，索引/长度错误、截断、所有权与原子保存检查。
- 三个现有船模的 C++ 与旧服务逐步对照：点移动、属性、显示、拓扑、保存点、
  分支历史和稳定 ID，独立比对完整模型、场景和 DXF。
- 错误文件、过期版本、写入失败、无效坐标、运算进程被终止，以及恢复后的撤销。
- 复用现有建模套件的约束、锚点、分组、标记等预期，并走实际 Qt 操作回调。

首轮有 3 个故障注入错误：同步读取 stdin 的服务未及时刷新 QProcess 对空闲
子进程的状态。改为检查进程句柄后再复用，现在整个套件为 1,943 pass、0 fail、
2 review、2 not_run、0 error。旧失败报告保留，不改测试预期掩盖问题。

测试代码为 `FreeShip-Tests/qt_document.py` 和 `qt/fbm_codec_tests.cpp`，与所有
诊断、安装记录一并保留。报告含各阶段秒数。真实桌面和完整视觉验收仍单列。

# C++ 面板、圆柱、求交与船型形变

2026-11-03：网格面板、圆柱、平面切割、图层求交、Lackenby 船型形变，以及
形变窗口使用的排水量和浮心测量，接入 C++ 文档服务。继续使用已有 Qt 窗口、
菜单、选取方式和撤销流程，没有另做一套界面。

`construction.cpp` 生成面板和圆柱控制点；`topology_edit.cpp` 建立面、折痕、
交点和控制曲线；`geometry_input.cpp` 从已验证的 FBM 数据建立计算输入；
`lackenby_edit.cpp` 负责剖面积积分、测量和迭代形变。每次编辑先构建私有候选，
恢复显示并验证成功后才进入历史。非收敛、锁定、非法输入或发布失败不提交。

## 保留的数值行为

圆柱沿用原来的插值控制环：先解 Single 矩阵，再旋转和沿轴生成两圈控制点。
不能把控制点直接放在规则圆上，那会改变细分后的曲面。矩阵求逆的主元选择、
消元顺序、三角函数和坐标赋值精度均保留。面板保持完整原点和端点尺寸；新点
不自动焊接到已有船体。

图层求交使用另一图层的原生细分面，按原来的三角扇、平面符号、点在三角形内
判断和端点距离限制插入控制点。原有点不移动，交点名称随 FBM 保存。平面切割
保留可见边规则和可选控制曲线。距端点过近、无法插入的新点直接跳过，避免旧
`InsertPlane` 把空指针加入后续排序列表。

对应旧代码：`FreeShip-Plus-Lazarus/Units/FreeSubdivisionControlEdge.inc:646`
在距端点小于 `1e-4` 时返回空值；`FreeSubdivisionSurface.inc:4067–4068`
未检查就加入列表，后面把它当控制点访问。本次 C++ 路径在插入处判断返回值。

Lackenby 保留原来的 40 区间积分、剖面镜像、曲线拼接及迭代停止条件。这里的
曲线拼接兼容路径独立于通用型线图算法，避免把通用算法的历史修正混入形变。
只修改选中图层控制点的纵向坐标；横向、垂向、项目尺度、标记和无关计算记录
保持。整体平移后的船体和显式中剖位置也参与验证。

FPC 与系统数学库的 `Power` 在部分迭代上有 binary64 末位差异。收敛因子只取决于
迭代次数，最多 100 项；本实现保存原 RTL 生成的十六进制常量。统一测试会编译
保留的 Pascal 数学探针，重新生成并逐位核对全部 100 项，不运行代码生成写入。

## 旧版按内存地址排序的问题

旧程序在生成网格后按对象地址分配部分新编号。平面切割还会按新点地址决定
拆面顺序。用同一个箱体、同一条切割命令跑两次，原服务出现两种结果：控制网
完全相同，但一处细分坐标分别为 `6.25` 和 `6.250000476837158`，场景字节随之
变化；DXF 和剖面文件相同。两份原服务输出都保存在测试夹具，并附来源和指纹。

C++ 用坐标及创建序号固定切割顺序，结果逐字节匹配第一份原服务场景。测试不
提高误差容限：新编号通过精确坐标映射后比较，所有属性、面朝向和重复项保留。
实时旧服务若产生第二份已记录结果，差异明确记为 `review`，并继续检查两边
各自的完整原始结果。任何其他数值或场景差异仍失败。

2026-11-03 背景/曲线定义迁移回归又遇到第三种旧版结果：曲线方向反转，两处
细分坐标末位不同。使用此前安装的旧桥接程序，完整重放相同建模序列，四次均
复现了这份模型和场景。证据见 `plane-box/provenance.json` 的第 3 份记录，
复现工具为 `maintenance/plane_oracle_replay.py`。原生预期仍固定为第 1 份，
没有替换原生基准或提高容差；已知旧结果逐份精确校验后记为 review，未记录
的差异仍失败。DXF 实体完全相同，但文本顺序差异继续单列 review。

## 验证和剩余范围

`qt_native_construction.py` 覆盖三种面板方向、小数坐标、倾斜圆柱、封口、切割、
图层求交、锁定拒绝、撤销重做、保存重开及近端点安全处理。
`qt_native_lackenby.py` 保留独立测量、目标变化、旧程序数值对照和失败回滚。
二者加入统一 `qt-document`；实际 Qt 入口继续由建模工作流测试执行。
该工作流已增加确认执行 Lackenby 后的撤销重做，以及确认平面切割后的撤销。
报告、构建和临时程序均在 C 盘，测试源码和必要夹具保留在 `FreeShip-Tests`。

独立诊断也可复用：CMake 的 `native_lackenby_probe` 是显式构建目标；
`qt_native_lackenby.py --probe` 可隔离计算层，`maintenance/lackenby_trace.py`
只在私有副本中加入旧核心逐站输出，`maintenance/lackenby_math.py` 核对 RTL
常量。它们没有混入产品工作流，也没有只存档后弃用。

0 fail、3 review、6 not_run、0 error。2,514 个安装文件的清单与指纹已核对，
核心程序与通过最终回归的二进制相同；旧安装包保留在

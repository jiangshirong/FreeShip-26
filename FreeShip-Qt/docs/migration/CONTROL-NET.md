# 控制网与细分输入约定

本轮的 `GeometryInput` 为原生细分计算服务。它从旧核心的控制对象直接导出，
不从四视图或型线图反推，也不使用显示三角网代替控制网。它不承担 FBM 保存、
编辑约束或完整文档恢复。

## 输入

JSON 标识为 `FreeShipGeometryInput`，版本为 1；C++ 定义见
[subdivision.h](../../src/native/subdivision.h)。

| 字段 | 含义 |
|---|---|
| `subdivision_mode` | 0 为混合三角/四边模式，1 为 Catmull–Clark 模式 |
| `precision`、`desired_level` | 原模型的精度元数据、目标级数；测试另指定实际查询的级数 |
| `points` | 原始控制点坐标和 Regular/Crease/Dart/Corner 类型，按来源顺序保存 |
| `edges` | 显式控制边的两个端点、折痕标记、所属曲线；保留未被面引用的边 |
| `faces` | 每个控制面的有向顶点环和所属图层，不按坐标重新排序 |
| `curves` | 控制曲线的有向点链和可见标记；闭合链保留重复首点的表达 |
| `layers` | 名称、来源层 ID、颜色、透明度、对称/显示/参与计算标记、展开标记、密度和厚度 |

下标只在这一份输入内标识对象。它不是正式文档中的长期对象 ID，也不保证跨保存、
加载或拓扑编辑保持不变；后续接入正式模型时需要建立明确映射。坐标相同的不同点
保持为不同对象，不能为了比较方便自动合并。

细分作用于完整控制网。图层的对称、可见性和参与后续计算的标记在这里原样保留，
不因此自动镜像或删除面。绘图、剖切和静水力对这些标记的解释属于后续流程；
属性传递正确不能冒充这些功能已经迁移。

锁定、锚点、永久直线约束、选择、历史记录、背景图、静水力设置和其他 FBM 字段
不属于这份静态计算输入。对已有坐标进行细分不需要它们，但编辑和保存需要。
不能把这份输入写成一个删掉其他信息的“新 FBM”。

## 每一级结果

第 0 级保留原控制点下标；细分后的点 ID 按控制面顺序、该控制面的子面顺序、
面内有向点序首次遇到时分配，随后按控制曲线的点链补齐尚未出现的点。
边按同一拓扑遍历首次遇到时记录，端点统一为
升序 ID，面仍保留完整有向环。没有按地址或坐标排序。

每个子面带原控制面、子面序号和图层；第 0 级仍是原控制面，子面序号为 `-1`。
边带相邻面、折痕、曲线归属与是否源于
控制边的标记。曲线保留方向、折角及是否独立于面网格的状态；孤立控制点和裸边
单列，不能当作“没有用到的内存对象”丢掉。

包围盒由这一快照实际引用的面/曲线顶点计算，空快照另有标记。它不等同于旧
`Surface.Min/Max`：旧重建末尾可能按控制点重新计算范围。比较双方使用同一个
快照口径，不拿不同含义的包围盒判定精度。

## 如何验证

旧核心探针在私有副本中构建，几何算法的 include 文件保持原字节。除构建所需的
无界面适配外，增加读取原始图层名、曲线显示值和边来源标记等观察接口，以及将完整性提示转换为可记录
错误的处理。它调用原 `LoadBinary`、`Rebuild` 和细分函数，不把新 C++ 算法重写
一遍后当作基准。

先将原对象导出的输入重新交回旧核心，逐级验证导出是否丢失语义；随后与 C++
结果逐字段对照。独立的小网格另检查可手算的顶点位置、面数、边界和朝向。
这些证据分别回答“是否保留旧行为”和“是否符合数学预期”。

旧对象保留的原始面层级、分配但未引用的对象数等只作诊断；它们不参与规范网格
编号，也不会用来替代实际拓扑。诊断差异仍单独保留，不能无声删除后宣称整个对象一致。

ShipCAD 只作可选参考。本轮重新组织计算数据和所有权，不引入它的窗口、控制器
或内存池。采用哪些公式、保留哪些行为，须在来源说明和测试结果中逐项交代；
它与当前 Plus 的共同输出也不能自动当作数学真值。

# C++ 控制网编辑

2026-11-03：基础控制网的 13 个命令已经迁到 `src/document/topology_edit.cpp`，
沿用现有 Qt 入口、选择和撤销流程。对应的 FBM 控制点、边、面、曲线、名称、
点组和依赖索引由 `Fbm::withControlNet` 写入。

| 范围 | 命令 |
|---|---|
| 基础编辑 | 新增点、新增面、单边拆分、折痕、锁定、面换层、删除点/边/面 |
| 组合编辑 | 批量拆边、顺序连接点、合并二度点、反转面、清除无面点、删除负侧 |

先在私有控制网中验证整批请求，再生成候选文件。锁定点、约束的两端、硬锚点、
重复或失效 ID、相交面边界、面外对角线、非流形新增面和过短边都会拒绝操作。
失败不提交历史，也不覆盖当前文件。存活对象沿用 ID；撤销后分支新建对象继续使用
递增编号。模型坐标仍是原 Single，拆边中点仍按原双精度求和后写回 Single。

删除曲线中的一条边时，原曲线销毁，两侧各有至少两个点才建立新曲线；新曲线继承
选择状态，不继承原名称。删点同时更新组成员，空组保留名称。约束和锚点的引用按
新控制点序号写入。项目设置、图层、图片、计算设置等无关块逐字节保留；几何变化
使剖切和流线缓存失效。未知尾部仍只允许原样保存。

本轮对照发现并保留了两项容易被函数名掩盖的旧行为：

- `FreeSubdivisionControlFace.Delete` 先通过 `Unreference` 从曲面移除面，因此后续
  清理块不会执行。删除面会留下线框边；删除点或边再移除被直接选中的关联边。
  迁移没有顺便改成“删除全部无面边”。
- 自由控制曲线在 `SubdivideFreeStanding(0)` 中修正折痕和端点类型。候选文件必须
  先包含这些类型，否则显示后的模型会与刚保存的候选不同。

合并二度点还依赖端点内部的边顺序：拆边后，新点先引用新边，再引用原边。
FBM 只有全局边序列，不能记录任意的端点内部顺序。因此会话绑定增加可选的
`point_edges`，与点 ID 数组一一对应，存完整有序边 ID；适配器验证后恢复这份顺序。
C++ 操作保留或更新它。撤销/重做仍按原行为重新载入 FBM，重建文件顺序；
进程故障恢复则恢复当时的会话顺序。它不是新 FBM 字段，也不写入用户文件。

提交前校验适配器返回的全部点坐标/类型/锁定、边端点/折痕、面点序/图层及输出
身份。适配器在外部文档模式下拒绝这 13 个旧编辑命令，不能悄悄退回旧算法。
适配器仍负责载入候选并生成尚未迁移的四视图网格和分析数据；完整型线图、场景
及 DXF 继续走已有原生计算。这里没有降低绘图或导出精度。

1.98 之前的 FBM 不能记录锁定标记。首次给这样的文件加锁时，适配器只做版本转换，
C++ 再执行锁定和写入；转换不额外产生撤销步骤。其他版本字段和未知扩展的限制
仍由编码器拒绝，不能把局部控制网写入称为全部 FBM 原生编码。

测试源码在 `FreeShip-Tests/qt_native_topology.py`、`qt/fbm_codec_tests.cpp`，
已接入统一 `qt-document`。对照完整模型、场景、DXF、剖面数据；另有明确的中点、
面方向、曲线分段、级联删除、清理、ID 不复用与保存重开预期。特别覆盖未经撤销的
“拆边后立即合并新点”，避免撤销重新载入把边顺序问题掩盖掉。
最终报告与安装指纹见 `FreeShip-Tests/maintenance/topology-installed-20261103.json`。

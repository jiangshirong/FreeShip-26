# 控制网基本编辑

2026-11-01。本轮把基本的点、边、面操作接到 Qt 主窗口，并同时恢复 StudioLight
主界面框架。命令仍由唯一的文档服务执行，新的型线图继续由 C++ 生成。
编辑、图形更新、撤销和保存回读是一条流程，不用显示三角网替代控制网。

## 已接入的操作

| 操作 | 实际入口与行为 |
|---|---|
| 新增控制点 | “点”菜单输入三维坐标，按当前单位提交 |
| 选择边、选择面 | 对应菜单进入选择；Ctrl/Shift 增减选择，四视图同步高亮 |
| 拆分边 | 在选中边的中点插入控制点；保留原边 ID，另建一段边和新点 |
| 设置、取消折痕 | 修改选中边；边界边不能取消折痕 |
| 建面 | 按点选顺序创建面，并指定已有图层；拒绝重复点、退化、自交和非流形边 |
| 修改面所属图层 | 选面后指定已有图层；重复指定原图层不增加历史 |
| 删除点、边、面 | 删除所选对象及原模型规则规定的依赖对象；先提示范围，可撤销 |
| 锁点、解锁 | 更新已有控制点；拓扑修改不能间接删除锁定或约束关联点 |

顶栏沿用原图标和分组。坐标、图层面板通过原功能类别按需打开。
完整 UI 保真状态见 [UI-FIDELITY.md](UI-FIDELITY.md)；本轮不把辅助线、动画或
其他窗口算作已经迁移。折叠、挤出、镜像和完整图层增删是后续操作，不混记为完成。

## 对象身份与失败处理

以前只有移动坐标，点、边和面的数量不变。删除或拆分会改变数组下标，因此本轮
改为保留已分配的 ID 槽位，删除后留下空位，新对象只向后分配。存量对象继续使用
原 ID；撤销、重做和失败回滚恢复原有对应关系，同时保留分配上界，避免撤销后
创建的新对象冒用之前已消失对象的编号。编号按文档和对象类型区分，重新加载
FBM 会产生新文档，不能拿旧文档编号操作新文档。

快照和保存历史只写现存对象；空槽不写成虚假点，也不写回 FBM。所有请求继续
检查文档 ID 和版本。旧编号、重复选择、空选择和锁点相关操作在修改前拒绝。
原模型、历史与原生场景生成仍在同一提交范围内，生成失败不提交半次拓扑变化。

早于 FBM 1.98 的格式没有锁点字段。首次锁点时提升最低保存版本，避免保存或重做
丢掉锁定状态；撤销仍恢复原格式和原状态。该问题用旧格式夹具、原对象读取器核对。

主要实现：

- `bridge/TopologyEdits.inc`：操作校验、原模型调用和 ID 重建。
- `bridge/ModelService.pas`：保留 ID 空位、历史和事务处理。
- `src/render/hull_view.cpp`：点、边、面拾取、选中高亮和失效选择清理。
- `src/app/studio_actions.cpp`：实际菜单及编辑入口。
- `src/app/topology_workflow.cpp`：生产程序里的隔离流程采集入口。

## 测试范围

统一入口 `FreeShip-Tests/run_tests.py --suite qt-topology`；直接入口为
`qt_topology.py`。覆盖盒体、合成曲面和 9a，逐步调用同一文档服务的原生及旧参考
生成路径，比较带属性的完整控制网、完整 DXF 和全部场景差异，不新设数值容差。

独立预期包括边中点、增加的点边数量、新面的有向顶点与三条边、删除后的旧编号
拒绝、撤销分支编号不复用、重复/非法操作无变化、锁点影响范围和组件失败回滚。
实际 Qt 程序执行菜单拆边、新点坐标对话框、按点选顺序建面、面图层对话框、删除
确认/取消、锁定/解锁、撤销/重做及两轮保存重开。最终文件再由旧参考路径完整回读。
确认使用普通 Qt 对话框，隐藏验证时保留隐藏属性，测试不会操作桌面。
这里没有继续使用 `QMessageBox`：Qt 6.8.3 的该控件在显示时会按原生弹窗状态重写
隐藏属性，见 [Qt 源码](https://github.com/qt/qtbase/blob/v6.8.3/src/widgets/dialogs/qmessagebox.cpp#L1547)。
原有属性和点拖动测试保留，
新增稀疏编号的边/面拾取、多选、隐藏图层和换文档选择清理。

已有基础细分仍有明确不支持的特殊拓扑，见 [原生型线图边界](NATIVE-LINESPLAN-APP.md)。
本轮也未宣称全部旧编辑工具已迁移。输出报告分别记录通过、失败、待看、未执行和
错误；隐藏窗口流程不代替实际桌面使用与外观验收。

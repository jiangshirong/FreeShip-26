# 第一阶段接口审查

日期：2026-11-01。审查对象是 [PROTOCOL.md](PROTOCOL.md)、`src/core/model_snapshot.h`，以及旧版读写、撤销和型线图生成路径。本文记录约束及待验证风险，不是新程序的测试通过报告。最新实施和验收状态见 [STATUS.md](STATUS.md)。

## 当前边界

计算服务持有唯一可编辑模型；Qt 只持有完整的只读快照和窗口状态。屏幕三角形、折线和标注不能反向变成编辑模型。四视图与型线图可以独立改变相机，但只能一起接收同一模型版本。

`model_snapshot.h` 已把原始控点/边/面与派生三角形分开，坐标使用 `double`；FSLP 继续保留原绘图顺序和完整坐标。这适合第一阶段。它没有控制曲线、交线对象、完整项目参数、背景图、板材和计算工况，不能当成完整的长期文件格式。

本轮已静态核对到的实现：文档身份与版本联合校验、JSON 整数上限、按核心浮点类型判定无变化、单独保存 ID 与序列顺序的对应、失败回滚路径、每轮生成前重置交线采样状态，已经进入服务代码。`model_snapshot.cpp` 也已检查格式、有限数、集合上限、重复 ID 和引用关系。下面列的相应验证仍须由本轮报告给出，代码存在不等于故障注入已经通过。

## 会话、保存和交付代码的补充复核

随后检查了 `src/app/model_session.*`、`src/app/main_window.*`、`build.ps1`、`package.ps1` 和服务实现。下列问题已经反馈并在新源码中检查到处理；这张表标的是代码处理状态，具体测试结果由本轮报告另列。

| 服务先切换文档，客户端才发现快照不合法 | 服务提交候选前补齐主尺度、单位、引用、大小、空 UUID、项目/图层名 NUL 等与 C++ 一致的检查。 | 非法元数据加载失败后，旧文档仍可继续编辑和撤销；产物在传输后损坏仍会停用服务，完整跨进程二阶段提交尚未实现。 |
| 纯 C++ 部署可能漏桥接或带上过期桥；编译后才算哈希可能误标源码 | `package.ps1` 验证桥接报告、来源和可执行文件，归集资源与许可到新目录；`build.ps1` 比较编译前后源码和测试指纹。 | 完整包离开构建目录后的运行、依赖资源和文件清单。`build.ps1 -Deploy` 仍只是 C++ 产物，不能单独当作完整包。 |
| 隐藏工作流包含 not_run，却把总报告写成 pass | 工作流总状态改为 partial。 | 上层汇总继续保留各项真实状态，实际桌面验收不由隐藏工作流替代。 |

本轮没有更改旧产品源码、正式程序和用户模型。预览修补只进入隔离桥接源码；背景图 JPEG 反复保存的旧保真问题仍应按 O09 单独追踪，不能借这次缩略图修补宣布已解决。

## P0：首条编辑流程必须封住的问题

### 文档身份要和版本一起校验

最初协议仅要求 `expected_revision`。关闭 A 后打开 B，两者都可能出现 `revision=1`、`point_id=1`；迟到的 A 编辑若只核对版本，会改到 B。

已向主任务提出，并获采纳：所有依赖当前文档的请求带 `expected_document_id` 和 `expected_revision`，服务检查两者；响应还要与请求 ID、预期文档对应。控制器串行处理不能代替服务校验。验证时保留 A 的旧命令，打开 B 后重放，必须拒绝且 B 的模型、撤销栈和输出不变。

### 生成失败不能留下“报错但已修改”的模型

`move_point` 不止修改坐标，还需要重建、生成模型快照、型线图及 DXF。若最后写文件失败，UI 可能仍显示旧版本，服务却已经修改；下一次保存就会写出用户没看到的状态。

已获采纳的处理是：保存旧模型状态和历史边界，所有产物成功后才提交新版本；失败回滚坐标、历史、修改标记和版本。`load`、`undo`、`redo` 也应具有同样边界。测试应分别在 JSON、场景、DXF 输出阶段制造失败，再检查快照和后续撤销行为；只检查异常文本不够。

### 对象 ID 不能来自易变数组次序

旧版 `Units/FreeSubdivisionSurface.inc::SaveBinary` 在写控点前调用 `FControlPoints.Sort`；`SaveToStream` 也有排序。保存、生成撤销快照、重新加载都可能改变下标，裸指针更不能跨进程或重建使用。

v1 承诺的是同一文档内坐标编辑和撤销/重做的 ID 稳定。实现必须保持单独的 ID 关联，或者使用确经验证的稳定映射；保存后不能让原 ID 指向另一控点。需要多控点、不对称坐标、重复坐标及多次保存/撤销样本。只测第一个未锁定点会漏掉这类错误。拓扑编辑和跨文件持久 ID 暂未承诺，不能提前开放依赖它们的命令。

### 保存成功分两步，但中间状态要明确

服务 `save` 只产生私有的 `saved.fbm`；目标文件安全安装成功后，UI 才发 `mark_saved`。失败或取消时保留修改状态。若目标已安装而 `mark_saved` 失败，文件已经保存，但当前会话仍应保守地显示有修改，并给出明确结果，不能谎报目标文件不存在。

旧版 `FreeSafeFile.pas::SaveProjectFile` 已有正式文件与备份保护。Qt 安装步骤要独立测试短写、拒绝访问、目标已有文件、备份失败和路径差异；不能先删除目标再重命名临时文件。自动测试使用临时副本，不触碰用户原文件。断电、网络盘和云同步不在普通文件测试的覆盖内。

## P1：精度、状态与导出

| 核对点 | 具体风险和处理 | 验证要求 |
|---|---|---|
| 原数值类型 | `Units/FreeTypes.pas` 的 `TFloatType=single`。C++ `double` 和 FSLP Float64 只是不再损失传输精度，不代表已把旧计算提升到双精度。输入点先转换为核心数值类型，再判断是否真的变化。 | 相邻 Single 可表示值、负值、英制、小尺寸与大坐标；经坐标输入、撤销、保存重开后核对数值。 |
| JSON 整数 | `quint64` ID/revision 如果经过 `toDouble()` 等浮点路径，超出精确整数范围会混淆；负数、小数和溢出也不可强转接受。 | v1 明确范围并严格读取；若以后需要整个无符号 64 位范围，定义十进制字符串等无损表示。用非法数字和临界值验证拒绝行为。 |
| 无变化操作 | 请求 double 与实际 Single 不同，但舍入后可能等于旧坐标。若照样建历史，会污染撤销并截断重做。 | 按核心实际存储值判 no-op；确认 `revision`、undo/redo、modified 和输出均不被假修改。 |
| 相互引用 | 点 ID、边端点、面点环、面图层、三角形图层必须存在；重复 ID 和不合法面环不能静默跳过。 | 加载器拒绝损坏快照。拒绝后旧视图仍可用，不发布半张模型。 |
| 资源上限 | 单行协议、JSON、三角网及 FSLP 都可能很大。只限制坐标绝对值不等于限制内存。 | 对文件字节、对象数、顶点数、字符串和请求积压设上限；报告错误，不截断几何后宣称成功。上限须容纳已有真实船型。 |
| ID 查找成本 | 初版服务 `IdOf` 逐次使用 `TFPList.IndexOf`；写边、面点环和捕获历史时反复线性查找，大控制网会产生平方级工作。 | 建指针到稳定 ID 的索引，或每次输出先建一次映射；分别测大量控点和大量派生三角形，不能只测小盒体。 |
| 快照一致性 | `model.json`、`scene.fslp`、`reference.dxf` 是三个文件；旧输出路径复用会让新旧内容混杂。FSLP 本身没有 document/revision 头。 | 每次请求使用新私有目录，清楚绑定版本；全部读取、验证后一起发布。后续磁盘缓存宜用版本清单与校验值，不按文件名猜身份。 |
| 可见性和对称 | 图层可见、用于静水力、可展开、出现在型线图是不同标志。`visible` 不能替代全部；对称网格不能重复镜像。 | 多图层、非对称附体、中心面、隐藏图层分别比较；保留已修复的 STL 图层对称行为。 |
| 水面口径 | 快照的 `waterline_z` 定义为模型最低 Z 加吃水；静水力代码另有参与计算图层和倾斜水面口径。 | 当前字段仅用于约定的显示。迁移静水力时另带完整工况和基准，不把一个水平面高度当作所有计算水面。 |
| 连续拖动 | 鼠标每次移动都往服务排队会产生旧画面追赶；每点事件一个 undo 又会淹没历史。 | 视图可实时预览，提交一次完整拖动；同一交互只建一次撤销。等待时合并待处理预览，正式命令不能悄悄丢失。 |
| 意外退出 | 服务崩溃后，界面仍能显示最后快照，却已不能可靠保存当前可编辑模型。 | 报告服务状态，阻止假保存；保留会话私有数据供恢复。重启服务是否恢复未保存编辑须明示，不能默认当作已实现。 |

### 显示与导出继续分开

GPU 可用相对原点的 Float32 坐标加速显示；这些坐标不能回写模型或作为 DXF 输入。极端放大时的精度回退也只是显示策略。导出从完整服务模型或已验证的完整产物取得，不能使用屏幕裁切、隐藏标签后的预览，或当前帧的临时拖动位置。

原 `Forms/FreeLinesplanFrme.pas` 的屏幕 `DrawSpline` 和 DXF `AddSpline` 在平面图投影上有明确差异，试点文档已记录。当前迁移保留各自输出，不在渲染重构中悄悄改公式。后续修正须用已知水线的独立几何预期，不能把原图截图作为唯一真值。

DXF 还会改变样条采样状态，当前流程必须保持“场景生成在前、DXF 在后”。新增常驻服务后要测重复 `snapshot`、保存、撤销再生成，避免第一次相同、第二次因遗留状态而变化。比较应保留坐标、连接、图层和颜色；只沿用现有比较器已经明确支持的实体排列和多段线遍历方向规范化，不新增容差或简化规则。

### 本轮另查出的折痕线导出副作用

`qt-migration-20261101-b` 的 9a 模型暴露了两种问题，不能统称为样条采样污染：

- 11 次拒绝命令后的再次快照，FSLP 填色三角形和标注完全不变，但黑色两点线段逐次反向。第一份有 177 条，后续每次多 4 条，最后 217 条；这些记录均是原坐标精确交换端点。
- 直接服务与真实会话/生产窗口的 5 份 DXF 差异均在 `Knuckle_lines`。同一条链会在不同位置断成两段，例如 66+56 点变成 64+58 点；重开后还可能变成一段。部分输出另有 78 条 LINE 方向反转。坐标、线段数量、图层和颜色没有因此改变，但多段线实体的分组确实变了，所以完整实体比较失败是有效发现。

根因在 `FreeLinesplanScene.pas::ExportDXF` 调用旧 `Surface.ExtractAllEdgeLoops`。`FreeSubdivisionSurface.inc::ExtractAllEdgeLoops` 按指针排序选择起点；`FreeSubdivisionEdge.inc::FGetPreviousEdge/FGetNextEdge` 和 `SortEdges` 又用 `SwapData` 翻转共享边。下一次场景生成读取这些边时，方向已经不同。`FGetNextEdge` 在终点找下一条边，却用两个起点是否相同判断翻转，也会令追踪折返或提前断开。清空交线缓存不能恢复这种边状态，重载能清除它。

处理边界已经确定：只在新桥接中改为**只读、确定性的折痕线提取**，保留原点、边和属性，不修改旧产品源码，也不改曲面、求交、浮点类型或采样精度。该修复针对导出组织方式及副作用，不能宣传为原算法精度升级。实现与最终回归状态另见本轮报告；上述 b 报告还出现源码在执行期间变化，不能作为交付验收。

验收继续分开记录：

1. **新服务自身一致性必须通过。** 同一模型的连续生成、拒绝命令后快照、撤销/重做、保存重开，以及直接服务/会话/生产窗口之间，FSLP 字节和 DXF 完整实体仍严格比较。
2. **冻结旧 DXF 的差异不能改成 pass。** 若完整实体比较因旧地址随机分链及共享边反向而不同，保留原比较结果为 `review`，列清改变的实体；另外提供折痕线坐标、颜色、图层、边的重数和连通关系完全一致的证据。旧分链没有唯一稳定的进程间结果，不把某次随机起点当成几何真值。
3. **范围外差异仍失败。** 非 `Knuckle_lines` 的任何差异，以及折痕线坐标、属性、边数或连通性变化都仍是 `fail`。通用 `dxf_geometry.py` 不为此降低比较门槛。

## P2：后续扩展前再定的接口

- **完整设置与选择。** 当前快照是第一条工作流的投影。打开后保存应由原服务保存完整模型，不从快照重建。选择状态是 UI 状态，但命令目标必须是服务确认的 ID。
- **增量更新。** 当前只承诺完整快照发布。以后补受影响对象集合、删除列表、设置版本和缓存依赖，不直接把“改动点附近几个三角形”当作细分曲面的完整影响范围。
- **拓扑历史。** 添加/删除/合并时定义新 ID、墓碑和撤销恢复，再开放命令。跨文件身份、导入合并及旧 ID 重用另行规定。
- **持久缓存。** 缓存是可丢弃的派生数据，磁盘上存储仍叫缓存。键应包括模型内容、影响结果的设置、算法与格式版本；文件路径、时间戳或程序版本单独都不够。写入失败不影响模型保存，读取失败回退到生成。
- **外部计算。** 后续沿用 `FreeProcess.pas` 与 `FreeCalculationFiles.pas` 的超时、输出契约、独立工作目录和整组发布；不能把返回码 0 等同于有效结果。
- **专业模型精度。** C++ 原生核心是否改用 double 需要单独决策、误差分析及文件兼容方案。界面迁移阶段不混做数值算法升级。

## 验收中不能省去的边界

1. 新版本回归记录新源码、样本、工具链和产物指纹。旧 Pascal 17 条修复的报告是对照资料，不是新保存路径或 Qt 界面已经通过。
2. 相同输入的模型语义、完整场景和 DXF 都要比；仅图片相似会漏掉单位、连通关系及未显示数据丢失。保存重开也要检查未在 Qt 展示的记录。
3. 失败路径独立于正常路径：坏文件、过期命令、未知/锁定点、非有限坐标、输出失败、保存失败、服务退出；拒绝后继续操作同一文档验证可恢复性。
4. 性能分别记录服务加载/重建、产物生成、传输解析、GPU 上传、首帧与连续交互。后台生成快不等于窗口首次打开快，离屏耗时不等于真实显示帧率。
5. 测试进入 `FreeShip-Tests` 的统一入口。桌面输入、焦点、可读性、打印和多显卡未覆盖时保留 `review`/`not_run`，不转成 `pass`。本次审查没有操作桌面。

第一阶段的目标是可以验证、可以继续扩展的完整编辑流程。新程序还未覆盖的功能见 [FEATURES.md](FEATURES.md)，不会因为使用 Qt 就自动继承原软件全部能力。

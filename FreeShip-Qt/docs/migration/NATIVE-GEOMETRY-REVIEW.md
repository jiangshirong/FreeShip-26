# 平面与样条迁移复核

复核日期：2026-11-01。本轮只验证 `src/native` 中的平面、样条计算，没有把它接到正式程序，也没有迁移细分曲面、完整剖切、静水力、FBM 读写或导出。

参照对象是当前本地 Plus 工作树和固定在 `4d89e1498cbcea7b2c0c6b26aa7c8964b42279cd` 的 ShipCAD。Plus 已包含本项目的修复，不能把它称为未经修改的上游版本。本记录包含独立源码复核及最终统一报告的核对结果。

## 迁移时必须保留的计算行为

| 项目 | 当前 Plus 的实际行为 | 本轮核对重点 |
|---|---|---|
| 数值存储 | `Units/FreeTypes.pas` 的 `TFloatType` 是 `Single`；点、平面、参数数组和二阶导数也使用它 | C++ 的点与计算数组使用 `float`，先保证现有结果，不在迁移时顺便改变精度 |
| 平面方程 | `PlanePointNormal`、投影和求交实际使用 `a*x+b*y+c*z+d=0`；`T3DPlane` 的减号注释已过时 | 以函数行为为准。代数值只有在法向量为单位长度时才是距离 |
| 样条参数 | 当前 `FreeSpline.inc::Rebuild` 累加欧氏距离，长度近零时均匀分配参数 | ShipCAD 对距离再开平方，得到另一种参数化，不能照搬。用不等距、不共线的点辨别 |
| 折角 | 内部折角点清零二阶导；反代遇到折角也清零；一个区间两端都是折角时按直线插值 | ShipCAD 缺少后两项处理。端点、中间点、相邻折角和折角左右都要覆盖 |
| 求值 | `Value` 接收 `Extended`；`H/A/B/a3/b3/h2` 依次存入 `Single`。`B` 单独计算，不能换成 `1-A` | 保存中间舍入位置，不合并公式；小于 `1e-6` 的参数区间返回右端点。域外参数仍按端部区间外推 |
| 一阶导 | `FirstDerive` 是参数两侧各 `1e-3` 的有限差分，端点改成单侧；参数及差分端点为 `Single` | 不能用解析导数替换后仍声称结果完全相同。解析期望与旧版差分对照分别验证 |
| 二阶导 | `SecondDerive` 在已存储的二阶导数之间线性插值；非正参数间隔用 `0.5` | 不是重新拟合，也不能把点数组当导数数组 |
| 样条求交 | 按 `Fragments` 均匀采样；采样点接近平面先追加，再按严格异号追加插值参数处的点 | 保留采样密度、顺序和可能重复的参数。ShipCAD 的近参数去重不是当前 Plus 的行为 |
| 空/单点样条 | Plus 的 `Value` 返回零向量，单点并不返回该点；部分数组访问没有有效定义 | 兼容已定义的求值行为。越界或旧版伪交点单列安全差异，不能算作数值等价 |

源码定位：`FreeShip-Plus-Lazarus/Units/FreeSpline.inc` 中的 `Rebuild`、`Value`、`FirstDerive`、`SecondDerive`、`IntersectPlane`；`Units/FreeGometry_Functions.inc` 中的 `DistPP3D`、`PlanePPP`、`PlanePointNormal`、`ProjectPointOnPlane`、`MirrorPlane`、`PlaneIntersectsBox`。ShipCAD 对应 `ShipCADlib/plane.cpp` 和 `spline.cpp`。更早的借鉴边界见 [SHIPCAD.md](SHIPCAD.md)。

## 数值对照不能省略的细节

FPC 的 `Extended` 与 C++ 的 `long double` 不能只按名称判断相同。首轮探针实测为 FPC 3.2.2、x86_64、Win64，`Single/Double/Extended` 分别占 4/8/8 字节；本机 MinGW C++ 的 `long double` 占 16 字节。不能直接用后者替换旧 `Extended`。JSON 参数经 `Double` 读取后再传入旧 `Extended`，C++ 对应入口因此采用 `double`。报告还记录了舍入模式、精度模式和构建参数。表达式中常量可能改变中间精度，实际差异以当前 FPC 运行结果为准。

C++ 验证目标禁用快速数学变换及乘加融合。对照至少区分控制点、参数、二阶导数、求值、一阶导数和交点参数，报告最大误差和比较数量。不能只比较最终截图、交点数量或一个宽泛的总容差；发现差异先定位第一个发生舍入变化的中间量。

首轮差分发现 `Rebuild` 中 `2.0/1.0/6.0` 的 C++ 默认双精度常量改变了中间计算。原 FPC 对象代码在这些位置使用单精度 SSE 指令，候选据此改为 `2.0f/1.0f/6.0f`；一阶导的参数加减 `1e-3` 则保留实际基准的双精度常量。这是按旧计算过程纠正迁移差异，不是放宽比较标准。汇编证据保存在测试报告的 `FreeSpline-Rebuild-asm.txt`。

两个探针把 `Single` 提升成 `Double` 后写 JSON，没有输出原始浮点位模式。数值读回并重构为 `Single` 后相同，可以证明这条传输路径下的有限数值一致，不能据此声称内存逐位相同；尤其不能证明正负零的符号位或 NaN 的载荷位。NaN、无穷的拒绝测试属于接口安全检查，不属于有限数值对照。

增广端点样本还暴露了一个原算法本来就有的精度限制。自然 V 形样条在 `t=0.9999999403953552`（`1-2^-24`）的理论二阶导 Y 分量为 `-1.430511474609375e-6`，旧、新实现都得到 `-1.9073486328125e-6`。这里插值比例 `1-2^-23` 本身可以精确存储，误差来自它乘以 12 后的 Single 舍入，再与 -12 相加时显现；绝对差为 `2^-21`，即 `4.76837158203125e-7`。这不是 C++ 新增差异，也不能因旧新版相同就说数学结果没有误差。

精确解析断言使用原来九个二进制有理参数样本；新增的节点及节点两侧样本完整保留在 Pascal 对照中。上述端点误差另列为 `review`，没有删除样本、改动计算核心或扩大兼容容差。它同时说明：通过有限样本对照不等于证明样条在全参数域上数学精确。

旧版探针直接调用当前 Plus 的真实函数，不能把新 C++ 公式重写成 Pascal 后充当基准。独立数学检查使用平面、直线、可手算样条等期望结果，与旧版对照相互补充。当前 Plus 没有对应的独立直线与平面求交入口，该项应标为独立数学验证，不能伪称旧版对照。

## 不应带回来的旧问题

- ShipCAD 的三点构面在共线输入下可能产生无效系数。本轮应明确标记无效平面，不继续除零。
- ShipCAD 的平行直线判共面没有对距离取绝对值，远离平面的负侧也可能被当作共面。验证正负两侧、共面线和非单位法向量。
- ShipCAD 重用求交结果时只重置计数，没有清空数组。本轮必须覆盖相交后再次相交、相交后无交点两种顺序。
- NaN、无穷值、不可表示的运算结果、非法索引和数量不能进入有效缓存。失败的编辑保持原控制点；失败的重建不能被标为已完成。
- Plus 对零平面、空样条等退化输入的返回值不全有几何意义。安全拒绝与旧版数值兼容分别记录，不把“少报交点”包装为精度提高。

当前候选明确改变了几类无效输入的处理：零法向量或法向量平方和在 `float` 中不可表示的平面无效；它的投影/镜像返回空结果，不沿用旧版的零向量。少于两个点的样条求交返回无交点。倒置包围盒、非有限输入、越界编辑、有限差分分母为零及不可表示的结果会被拒绝。单点参数数组在候选中有定义，但旧版对应数组访问不安全，因此不做这一字段的数值等价断言。这些是接口边界，不是对有效船型精度的放宽。

另一个明确差异是零采样段：Plus 此时只检查参数为零的起点，可能给出看似完整的求交结果；候选对两点及以上的样条拒绝零段数求交，但仍允许样条求值，并在拒绝前清空传入的旧交点。测试保留旧版的真实结果，把这一项列为行为差异。

本轮独立复核还找到了候选直线求交的一处问题：平面法向量为 `(1e-18,0,0)`、直线起点为 `(1,0,0)`、方向为 `(1e-30,0,0)` 时，点积在 Single 中下溢成零，原候选会误判为平行，实际上应交于原点。修正只针对这个没有 Pascal 对照入口的新 API：点积、平面代数值、参数和坐标在 Double 中计算，并用短补偿求和处理大数抵消后的小余量。坐标使用尚未舍成 Single 的参数，最后检查输出范围再转换。原投影、镜像、盒相交和样条计算没有因此提高中间精度。

另一个独立反例全部使用二的整数幂：法向量 `(2^60,2^-60,2^60)`、方向 `(2^-60,2^-100,-2^-60)`、起点 `(0,1,0)`，点积为 `2^-160`，正确参数为 `-2^100`，交点为 `(-2^40,0,2^40)`。普通 Double 顺序相加仍可能把 `1+2^-160-1` 算成零，补偿求和避免了这次误判。这些反例进入新 API 的独立数学测试，不伪称 Pascal 兼容证据，也不据此承诺所有浮点输入都精确。

## 静态复核

已检查最终 `geometry.h`、`plane.cpp`、`spline.cpp`、`PROVENANCE.md` 和 CMake 接线：

- 计算库只依赖 C++ 标准库，没有 Qt、窗口、文件读写或全局模型对象；JSON 测试入口允许依赖 Qt Core。
- `FreeShipQt` 不链接 `native_geometry`，验证目标需单独构建。已验收程序继续使用原计算服务。
- 点和折角改变后使派生数组失效，读取时才重建。相同值不重复失效；采样数量改变不影响样条系数，只影响求交采样。
- 重建使用临时数组，成功后才替换缓存；求交先清旧结果，再临时组装新结果，避免残留和半成品输出。
- 源文件保留 Greg Green、Martijn van Engeland 及 GPL 第 2 版或后续版本声明，也注明当前 Plus 的后续贡献者。已独立重算 `third_party/shipcad/provenance.json` 中 ShipCAD 的四个文件及许可、Plus 的三个文件指纹，全部与实际源文件一致；许可副本与来源文件完全相同。逐函数修改说明与最终代码相符。

# 附加质量计算

2026-11-04。Qt 已接入从当前船型生成输入、运行 AddMass、读取结果和经验公式后处理。
入口为「计算 → 水动力专用工具 → 附加质量计算」。原来的 AddMass 输入文件导出仍保留。

矩阵、等效椭球和经验系数分别显示，可以保存 CSV、TXT、JSON、PDF。
工况保存为单独的参数文件，不冒充 FBM 中已有的计算记录。修改工况、计算失败或取消后，
上一份完整报告继续保留。计算不修改模型、撤销历史、型线图或 DXF。

## 实现边界

- 文档、输入生成、进程管理、结果解析和后处理均为 C++。数值求解仍使用外部
  `ADD_MASS.EXE`；它没有被重写为 C++，也没有加入本交付包。
- 输入复用 `grid_export.cpp` 的型值生成器。读取当前版本已校验的三角面快照和控制网，
  不重绘旧版窗口、不降低采样精度。公英制模型均转为该求解器要求的米、千克。
- 目前只支持能用单值半宽表表示的对称单体船。多体、非对称、漏水、重复正半宽等情况
  明确拒绝，不用虚构的型值补齐。面元类型、数量、精度、吃水、水深、漂角、航速和角速度可设置。
- 每次计算使用独立工作目录，运行时没有终端窗口。取消会结束求解器，110 秒超时也会停止。
  输入、原始输出和日志保存在本次工作区，避免读取上一轮遗留的 `OUTA`。
- 严格检查 20 行结果、6×6 矩阵及行列编号、有限数字、面元数量、缩放除数和回传工况。
  矩阵不强制对称化，也不把无效数字换成零。等效椭球的未定义值单列为空，并给出提示。
  数据表、CSV 和 JSON 保留原求解器写出的数值；软件没有增加求解器本来没有输出的精度。

## 上游流程中实际发现的问题

来源：`FreeShip-Plus-Lazarus/Units/FreeEdit.inc` 中
`ExportAddedMassInWorkspace`，以及 `Forms/FreeAddMassOutputDlg.pas`。
协议和经验公式保留原 FREE!ship/Plus 作者署名，未使用 ShipCAD 的计算实现。

1. 河船且 `Cb >= 0.8` 时，上游在给 `k11/k22/k66` 赋值之前就乘以修正系数并显示。
   Qt 不输出这组无依据的河船附加修正；已明确赋值的河船基本公式、正负加速度公式仍计算。
   海船分支的这组修正有已赋值的输入，因此保留。
2. 河船适用范围检查反复覆盖同一个错误编号，最后只显示一个问题。Qt 一次列出全部不满足项，
   并停止经验公式外推。原代码执行边界为 `L/B <= 8.5`，文字却写 8.6；当前采用执行边界并明确记录。
3. 上游读取固定长度字符串数组，没有完整验证矩阵数字。Qt 会拒绝残缺、NaN、错误工况等结果。
   一个独立箱形输入确实能让求解器正常退出却输出 NaN，因此退出码为零不等于成功。
4. 本机原始求解器在未设置环境变量时出现 `Illegal value for CONVERT`。仅在它的子进程中设置
   `GFORTRAN_CONVERT_UNIT=native` 后，独立椭球样本及真实船模均成功。此变量使用 GNU Fortran
   [官方支持的本机数据表示选项](https://gcc.gnu.org/onlinedocs/gfortran/GFORTRAN_005fCONVERT_005fUNIT.html)，
   未修改外部二进制或系统环境。原 EXE 的 SHA-256 写入结果，便于区分求解器版本。

海船和河船经验公式仍属于原有方法。主尺度沿用工程设置，Cb 使用所选吃水的实际水线长、
水线宽和排水体积计算，报告记录实际采用值。未取得独立工程依据的修正不会自行补造。

# FreeShip 26 增量更新

Windows 客户端通过签名清单发现新版，下载缺失的数据块，在本机合成完整安装器。
用户确认后退出程序，安装器执行原有 MSI 事务；失败时仍使用已验证旧 MSI 恢复。
不直接替换 MSI 管理的文件，不修改船模、计算精度、导出格式或偏好位置。

## 地址与服务器迁移

初始地址为 `https://updates.freeship26.work/freeship/stable/latest.json`。
服务器已有覆盖该 IP 的 HTTPS 证书与自动续期；FreeShip 使用独立静态路径，
不接管 AimArena 的代理、证书或端口。

有固定域名后优先使用域名：迁移服务器时同步数据、配置新机证书、修改 DNS，
旧机保留到 DNS 缓存和进行中的下载结束。域名不变时不必发布新版客户端。

IP 或域名地址本身改变时，旧地址发布包含 `next_endpoint` 的**签名清单**。
客户端验证已有内置公钥后记住新地址。旧地址提前关闭、用户从未收到迁移清单时，
客户端无法凭空知道新地址；应保留旧地址的过渡服务，并提供新安装包。
HTTPS 证书与发布签名密钥用途不同，不能用服务器新发来的公钥替换信任根。

## 分块与缓存

- 内容决定分块边界：最小 16 KiB、最大 256 KiB，目标约 64 KiB 量级。
- 大文件独立 CAB、小文件按稳定路径哈希分组；CAB 不整体压缩。选出缺失块后，
  每块使用 gzip 压缩传输，避免少量变化破坏整个软件包的差分。
- 本机基准来自原安装器保留的当前 MSI。每块与合成 EXE 都检查 SHA-256。
- 最多同时下载四块；已校验下载块可跨失败重试复用。下载清单时允许使用旧版本，
  不占用 UI 线程。程序启动 30 秒后才后台检查，可关闭自动检查，也可从菜单手动检查。
- RSA-3072/SHA-256 签名覆盖版本、产品系列、有效期、大小、每块摘要和新地址。
  生产客户端只允许 HTTPS，不接受任意公钥、测试目录或基准路径命令参数。
- 签名清单默认有效 30 天；发布维护需在到期前重新签发清单。过期时停止更新，
  不影响离线使用软件。签名私钥仅保留在发布者本机受限目录，不能上传服务器。
- 更新缓存只保留当前待安装 EXE 和本轮分块；安装器继续保留当前及上一代恢复包。
  下载被取消或进程结束不修改安装目录。下轮清理不再引用的自有分块。

目前为 Windows MSI 发行通道。未使用安装器登记的开发/便携目录不冒充已安装版本，
需要先进行一次完整安装，建立可恢复的更新基准。Linux 包管理与签名发行另行处理。

## 发布

`tools/updates/init_identity.py` 在 `%LOCALAPPDATA%/FreeShip26ReleaseIdentity/`
创建签名密钥，仅将公钥与 HTTPS 地址写入 `tools/updates/channel.json`。
保存离线私钥备份；丢失私钥后，现有客户端不会自动信任另一把新钥匙。

1. 构建并验证新的运行包。版本必须递增，已发布同版本不能换内容。
2. 使用 `tools/build_installer.py --version X.Y.Z` 构建安装器。
3. 使用 `tools/update_release.py --setup ... --output ... --key ... --version X.Y.Z`
   分块、压缩和签名；可用 `--base-msi` 生成与历史基准的实际下载量比较。
   用 `--release-notes notes.json` 将该版本的更新说明写入签名清单。JSON 按界面语言代码组织，
   每种语言使用 `bug_fixes`、`improvements`、`features` 三个数组，每项是一条简短的变更。
   缺少当前界面语言时优先显示英语，其次显示中文。空栏目在窗口中隐藏。
4. 用 `tools/updates/upload_release.py` 上传；凭据从终端或私有标准输入读取。
   服务器核对所有块的哈希后，才原子切换 `latest.json`。不下载整包来校验。
5. 验证公网 HTTPS、签名和客户端实际更新；单独保留安装失败及回滚报告。

单个客户端完整性检查不能代替代码签名信誉。当前清单签名确保自动更新来源；
Windows Authenticode 证书、SmartScreen 信誉是不同事项。

## 带宽与流量

100 人同时在线并不能单独确定所需带宽，必须给出目标完成时间或每人速度。
更新量 S MiB，100 人都希望 T 秒完成时，平均有效出站为 `838.8608 × S / T Mbps`。
2000 次下载的有效流量为 `1.953125 × S GiB`。实际还包含清单、协议开销、失败重试；
容量规划可另留余量，不能将余量当作已经测得的流量。

2026-11-13：真实原生运行包仅改说明文件和版本，完整分块压缩下载为 53,652,846 字节，
基于旧 MSI 增量下载为 1,378,144 字节（约 1.31 MiB），复用 100,435,825 字节。
100 人/60 秒对应 18.38 Mbps，2000 次对应 2.57 GiB。
该样本不代表任意 UI 代码修改。C++ 文案、布局、动画通常改变 EXE，工具链、链接顺序、
依赖升级也会影响差分大小。外置译文与图片更新和重新编译的更新必须分别测量。

0.1.3 签名清单实际为 272,176 字节。现有检查与下载各读取一次清单，若按这两次请求
估算，前述 1.31 MiB 差分样本总有效出站约 1.83 MiB/人，100 人/60 秒约 25.63 Mbps，
2000 次约 3.58 GiB。重复检查、安装后重启检查、失败重试与 HTTPS/TCP 开销另计。
不能将仅分块的大小冒充整个会话的全部流量；每额外检查 2000 次约增加 0.51 GiB。

## 回归

统一入口：`python -B FreeShip-Tests/run_tests.py --suite incremental-updates --runtime FreeShip-Qt/dist`。
`incremental_updates.py` 保存测试源码，使用独立测试密钥、回环服务、产品标识和安装路径；
由统一入口放到独立的非输入桌面。验证差分逐字节重构、断点复用、损坏缓存、坏签名、
过期、降级重放、错误产品、越界数据、地址迁移，以及真实 MSI 升级与提交后失败恢复。
`qt-close-controls`/`qt-window-chrome` 通过实际更新菜单回调检查更新窗口。
公网交付、自动重启和实际用户体验应与这些自动化结果分别记录。

公网校验入口为 `--suite public-updates --baseline <安装器输出目录>`，基准目录须含
`installer-manifest.json`。先访问独立验证通道，用正式公钥重构安装器；如果本机
已安装的正式更新程序与该发行版哈希一致，再调用其只检查模式验证正式通道。
这个检查会更新本用户的更新缓存，不修改模型、偏好或安装文件。

首次发行的本机安装版：`%USERPROFILE%/AppData/Local/Programs/FreeShip26Qt/FreeShipQt.exe`。
原 `FreeShip-Qt/dist` 仍是开发目录，不会被 MSI 当作更新目标。

# 流线追踪与计算参数保存

2026-11-03。沿用现有 Qt 窗口和 StudioLight 外观，本轮替换计算与写入路径。

## 流线

四视图中的流线现在由 `src/native/flowlines.cpp` 生成。它直接使用 C++ 细分网格，
与法线显示共用顶点法线。水下三角形、边的相邻面和初始方向每个网格只建一次，
供该工程的所有流线使用；追踪过程中不再反复扫描两个顶点的相邻面列表。

流线种子、投影方向和图层内的面顺序进入缓存键。改点、改精度或改种子后重建，
相同输入可以复用磁盘结果。这里验证的是工作进程重启后的缓存，不是整个 Qt
应用的跨重启缓存验收。模型文件中仍保存原有定义，没有新增不兼容格式。

原程序有一处明确错误：

- `FreeShip-Plus-Lazarus/Units/FreeFlowline.inc:489` 声明局部变量 `Param`，
  第 550 行传入求交函数，第 573–575 行用它插值下一段的方向。
- `Units/FreeGometry_Functions.inc:751` 的 `Lines3DIntersect` 虽然声明了
  `var Param`，函数体却没有赋值。因此后续方向可能受未初始化内存影响。

C++ 明确返回交点在三角形边上的比例 `mub`。测试中的旧核心隔离副本也只在这里
补上赋值，再做完整坐标对照；原 Plus 文件没有修改。另有独立平面样例：相邻
顶点的方向不同，正确的边比例必须让下一交点落在 `(3.897435897…, 2, 0)`，
不能靠两个实现一起写错来通过测试。

其余已有的追踪约定，包括 Single 存储、三角形顺序、水线截断和最多 5001 步，
继续保持。流线是贴着船体曲面的几何追踪，不是 CFD 求解结果。

## 计算设置

`src/document/analysis_edit.cpp` 接管两类请求：

- 吃水表范围、稳性角度与排水量列表、纵倾、重心高度及自由纵倾开关。
- 15 种阻力/推进计算器中，FBM 已定义的输入字段与水密度。

类型、上下限、列表长度、工况数量和 Single 舍入后的严格递增均在 C++ 检查。
写入与撤销是一笔文档事务；旧文件按需升级。无变化或空修改不升级文件，也不
增加撤销记录。整个请求先验证，发布失败时恢复文档和历史。

保存参数现在是显式修改：没有提供的字段保留原值和原字节，不再实例化旧窗口，
也不再借助 getter 顺带更改其他控件。完整窗口提交的输入仍逐字段与旧路径对照。
显式“估算湿表面积”在 C++ 使用输入的吃水和尺寸，不读取隐藏窗口未初始化的
`Tc`、`WlArea` 成员；缺少有效尺寸时结果为零。估算公式的独立正值样例另行检查。
FBM 原本没有存储位置的临时选项没有被擅自写进其他字段。

字段声明和存储偏移由保留在测试工程中的 `maintenance/generate_analysis_fields.py`
生成，记录 33 个原文件的 SHA-256。它只读取声明、字段映射和范围，不自动翻译
公式。生成的元数据随程序编译，运行时不读取 Pascal 源码。

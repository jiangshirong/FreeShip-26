# 原生运行包

日常运行包只带四个 C++ 程序：Qt 主窗口、文档服务、型线图生成器和几何导出器。
旧 Pascal 对照程序及测试探针留在开发包，运行包不再携带它们。
这个改动处理交付依赖，不改船面计算、型线图采样、导出算法或界面布局。

## 生成方式

`package.ps1` 继续生成带对照程序和测试工具的开发包。
从验证过的开发包生成日常运行目录，用：

```powershell
./package-runtime.ps1 -FromRuntime C:/FreeShip26-MultihullTests/runtime -DeployDir C:/FreeShip26-NativeRuntime
```

目标必须是新目录。默认不带本机的外部计算工具路径；本机更新时可以加
`-KeepLocalSolverReference`，仅保留 `calculation-tools.json` 中已有的绝对路径。
CALCPROP 等外部工具不随包复制，仍需单独安装及核对分发条件。

脚本先核对开发包清单及每个文件的 SHA-256，再复制到临时目录，复核后整体改名。
清单缺项、文件改动、额外未记录文件、越界路径、目录联接及不足 3 GiB 的磁盘余量都会拒绝。
已有目标不合并、不覆盖；失败保留现场，原包不变。运行包自己的清单记录源包指纹、
打包脚本指纹、排除文件、完整文件指纹及 `native-portable` / `native-local` 类型。

## 资源与兼容范围

`bridge` 目录名称继续保留，因为图标和偏好资源仍从这里读取；目录存在不表示
启动了 Pascal 程序。里面保留 Themes、Languages、locale、原源码归档和来源记录。
StudioLight 的图标、中文标注资源、文档、COPYING 和第三方来源文件逐字节保留。
用户设置、船模及旧 Win+R `fs` 入口不作修改。

开发用测试探针不属于日常运行依赖。需要独立 Pascal 对照或测试可执行文件的套件，
仍传开发包；不能把它们在日常包里的缺失当成迁移功能退化。
新统一入口 `qt-runtime-package` 对无 Pascal 程序的实际运行目录执行：

- 三个模型与同版开发包的控制网、船面、型线图场景和 DXF 精确对比。
- 原生打开、新建、编辑、撤销/重做、保存、失败回滚、静水力、IGES 和板材展开。
- 实际 Qt 编辑回调、中文/俄文路径打开及跨进程恢复上次模型。
- 原生 B 系列计算及报告导出；单独安装的 CALCPROP 三项真实计算与导出。
- 打包错误输入、清单篡改、目标保护、目录联接和空间不足的拒绝行为。

测试通过后从候选目录更新 `dist`，再对安装目录运行同一套件；前一个安装目录保留回滚。
结果和安装指纹见 `FreeShip-Tests/maintenance/native-runtime-delivery-20261109.json`。
报告写 C 盘，受统一入口的 8 GiB 总量和 3 GiB 余量限制约束。

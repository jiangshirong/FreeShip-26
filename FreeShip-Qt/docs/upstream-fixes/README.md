# 从上游继承的问题与本项目修复

整理日期：2026-11-12。

FreeShip 26 在迁移过程中修复了一批文件安全、单位换算、几何导出和静水力计算问题。这里集中说明原来会发生什么、修改在哪里，以及已有证据能支持到什么程度。

**本文中的“原版”特指 FREE!ship Plus in Lazarus 的固定提交 [`1de17e99`](https://github.com/markmal/freeship-plus-in-lazarus/tree/1de17e99fb2b1cc559cdf27c5cafb595a627a641)。** 不代表最初的 FREE!ship、所有分支或作者后续版本都有同样问题。原项目提供了本项目的建模与计算基础，原作者署名和许可证继续保留。

- [修复清单与代码依据](catalog.md)：沿用原记录 01–18，补充迁移阶段确认的 19–22。
- [可用于项目 README 的说明](README-excerpt.md)：挑出对工作数据或工程结果影响较大的问题，用实际操作说明后果。
- [证据清单](evidence.json)：固定上游文件、当前实现和历史报告的指纹。报告是历史运行证据，本次整理没有重新运行整套数值测试。
- [早期上游问题档案](../../../FreeShip-Plus-Lazarus/Docs/上游问题记录/README.md)：保留原排查、三批修复和社区来源，不覆盖当时的失败记录。

## 哪些最值得向使用者说明

| 优先说明 | 触发条件 | 可能出现的后果 | 记录 |
|---|---|---|---|
| 保存失败的文件保护 | 保存已有项目时写入或替换失败 | 正式文件缺失或不完整，需要从备份找回 | [01](catalog.md#u01) |
| 打开失败的当前模型保护 | 打开损坏、截断或无效项目 | 当前内存模型被提前清空，尚未保存的工作难以找回 | [02](catalog.md#u02) |
| 报告不应改动船体 | 自动移至基线开启，船底不在零位，且存在锁定点 | 普通点移动、锁定点不动，可能改变船体形状 | [18](catalog.md#u18) |
| 单位切换保持物理位置 | 公制与英制切换 | 船体缩放了，剖面站位却留在旧数值位置 | [06](catalog.md#u06) |
| 多轮廓静水力计算 | 月池、多个分离浮体等截面 | 面积、惯性矩以及由它们推导的稳心指标可能错误 | [19](catalog.md#u19) |
| 惯性矩单位一致 | 按旧窗口的 t·m² 标签填写 RVRSSHIP 参数 | 输入主机惯量可能比求解器所需值小 1000 倍 | [22](catalog.md#u22) |
| STL 遵守图层对称设置 | 导出非对称图层或已建完整模型 | 文件多出镜像面，与原模型不一致 | [13](catalog.md#u13) |
| 失败计算不能冒充成功 | 外部程序退出错误、卡住或没有生成新结果 | 一直等待，或继续走结果读取流程，存在旧输出混用风险 | [11](catalog.md#u11) |

这里没有“必然导致翻船”“一定造成加工事故”之类结论。数值错误和几何错误可能影响后续判断，但没有事故调查或实船证据，就不能把可能影响写成已经发生的工程事故。

## 分支和证据要分清

01–17 的三批修复首先落在本地 Lazarus 分支；Qt 版对应实现及测试入口在清单中另列。08、09 是旧对象状态管理的具体缺陷，Qt 不使用同一实现，不能冒充在 C++ 中再次修复了两个同样的错误。18 的处理落在 Qt；19–22 补入迁移期间的确认记录。

编号是方便追踪的记录号，不是可相加的漏洞评级。05、18、19 等条目包含相关的多个现象；同一根因影响多个报表，也不按报表数量重复计算。建议公开介绍具体问题，而不是宣传“修复了多少个严重漏洞”。

早期 01–17 的最终历史回归为 1403 项通过、3 项待复核、3 项未执行。原始报告总状态是 `partial`，不能改写为“全功能验收通过”。Qt 的报告有各自日期、版本和范围，不能用旧 Pascal 测试替代当前 Qt 验收。

## 不算作上游已修复缺陷的内容

- 船型 13 的 **0.91 / 0.091**：仍未核定，不能写“已修正风阻系数”。见[复核记录](../migration/INERTIA-WIND-REVIEW.md)。
- Qt 迁移时出现的型线图覆盖四视图、标签互斥、保存确认、重复船面防护遗漏等：属于本项目自己的回归或防护补齐，分别记录在迁移文档，不归罪于上游。19 条只讨论能追到固定上游实现的面积与惯性矩算法。
- 渲染更流畅、缓存、剖面线即时反馈、自动恢复、安装器升级回滚：可写为性能或可靠性改进；没有固定上游缺陷证据时，不混进本清单。
- 社区里已经由上游作者修复的问题，例如已回复修复的 IGES 对称路径，不算本项目成果；13 条是另一个 STL 导出路径。
- 未完成的接收软件、实船、水池、实体加工和完整桌面验收，不能因自动回归通过而写成已认证。

后续新增条目至少写清：固定原代码、触发条件、可观察后果、本项目修改、回归入口和未覆盖范围。只有优化猜想或尚未核定的数值，先保留为待核查。

本次文档核对工具保存在 `FreeShip-Tests/maintenance/collect_upstream_fix_evidence.py`。它只检查引用文件、固定上游行号、源码指纹和历史报告，不启动软件或重新计算；输出为本目录的 `evidence.json`。本轮核对了 16 份固定上游文件、11 份当前实现、26 个测试入口及所引用的历史报告，没有缺失链接或报告哈希不符。
